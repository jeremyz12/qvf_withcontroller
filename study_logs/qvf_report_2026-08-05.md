# 一、当前完整结构与逐段代码讲解

## 1.1 总体架构

```
用户问题
   │
   ▼
[1] 检索层         稠密 top-10(最优配置:全上下文投喂,跳过截断)
   │
   ▼
[2] 抽取层(LLM 唯一的工作)
    species2 契约:记忆轮 → 结构化记录
    〈实体, 槽位, 值, 逐字原文锚点, 物种标签, 条件, 文本内日期〉
    + 查询侧:时间范围分类(问当前 / 问历史)
   │
   ▼
[3] 裁决层(~150 行确定性 Python,零 LLM)
    按物种标签与查询范围分发政策(详见 1.4/1.5)
   │
   ▼
[4] 投喂层:减法原则
    只删被证实过时的轮,其余全保留;附裁决注记
   │
   ▼
[5] 阅读器(普通模型)作答
```

设计原则一句话:**LLM 只做符号方法够不着的语义感知;所有决策是可读、可单元测试、可回溯的代码。**

## 1.3 抽取契约(species2)——每个字段在干什么

`ExtractedRecord`(每条记忆记录):

| 字段 | 内容 | 下游用途 |
|---|---|---|
| `source_memory_id` | 来源轮 ID | 删除/保留以轮为单位执行 |
| `source_span` | **逐字**原文片段(复述即无效) | 防幻觉锚点;变更语言检查的检材 |
| `entity / slot / value` | 谁的什么属性是什么值 | 链组装按 slot 聚合 |
| `temporal_relation` | **物种标签**:replacement / correction / contradiction / cessation / unresolved | 裁决层的分发依据 |
| `relation_target_record_ids` | 被替换的旧记录指针 | 删除的对象由此确定 |
| `slot_cardinality` | single / set / unknown | 集合槽(兴趣类)排除"最新者胜" |
| `condition` | 适用条件("上班时"/"周末") | 条件共存路 |
| `stated_date` | **正文里**陈述的日期(文档场景无元数据时间戳时的回退) | 日期裁决 |
| `implies_stale_slots` | 本更新连带失效的其他槽位 | 跨属性依赖(T2) |

查询侧 `query_temporal_scope`:current / past_or_change / unclear——历史型问题的旧状态是证据不是噪声,必须放行。

提示词 11 条规则要点:逐字 span、时间戳晚≠更新(规则9)、冲突对扫描(规则10:抽到一个值必须回头抽同槽位所有竞争值)、文本内日期(规则11)。

## 1.4 裁决层逐行讲解——问当前态的路(优先级从上到下)

以下为 `run_minimal_rules` 中当前态分支的忠实逐行注解(行号对应 `scripts/run_decisive_stale.py`,以 freeze-20260805 为准):

```python
# ── 入口:一次抽取,得到 records + 查询范围 ──────────────────
extraction = extractor.extract(question, retrieved, date, contract="species2")
rel  = extraction.records                       # 全部记录
repl = [r for r in rel if r.temporal_relation in ("replacement","correction")]

# ── 路 0:不可变槽位分歧(新)────────────────────────────────
if _immutable_slot(query.slot) and 同槽位值分歧 > 1:
    # 生日/兄弟数/血型…不可能"被更新"——分歧=错误信息vs真值
    # 政策:永不最新者胜;全量投喂 + 佐证计数注记 + 矛盾阅读器
    note = _corroboration_note(rel)   # "值X有N轮独立支持;值Y有M轮"
    return 矛盾阅读器(question + note, 全部retrieved)

# ── 路 1:终止(cessation)───────────────────────────────────
if cess and not repl:
    # "我不健身了"——终止声明本身就是当前答案
    删除被终止状态的来源轮; return 阅读器(其余全部)

# ── 路 2:条件共存(conditional)─────────────────────────────
if 同槽位记录带 >=2 个不同的非空 condition:      # 收紧后的触发条件
    # "上班咖啡/周末茶"是共存不是替换——时间切片是范畴错误
    注记 = "各值在各自条件下并存,按问题所问的条件作答"
    return 阅读器(question + 注记, 全部retrieved)   # 减法原则:不删任何轮

# ── 路 3:矛盾(contradiction)───────────────────────────────
if contra and not repl:
    # 事实性分歧,无更新语言——近因不是证据
    return 矛盾阅读器(question, 全部retrieved)      # 全量投喂(修复后)

# ── 路 4:替换(replacement)= 主手术路 ──────────────────────
if repl:
    stale = set()
    for r in repl:                                # r = 新状态记录
        for t in r.relation_target_record_ids:    # t = 被替换的旧记录
            # 时间健全性检查(新):被删轮必须严格早于替换轮
            # (维基差分类近重复文本会让抽取器搞混替换方向,
            #  没有这一行会把当前版本连同过时版本一起删)
            if 旧轮日期 >= 新轮日期: continue
            stale.add(旧记录.source_memory_id)
    filtered = [m for m in retrieved if m.id not in stale]   # 减法投喂

    # 前提反驳注记(新):被替换的旧值出现在题面里
    # (错误解剖:88% 的陷阱失败是复读题目预设的过时值,
    #  记忆手术删不掉题面里的值,必须显式反驳)
    if 某旧值 逐字出现在 question:
        注记 = f"题目预设的'{旧值}'已过时,后被'{新值}'取代;按当前状态作答"

# ── 路 5:值分歧但无替换标签(conflict)──────────────────────
elif 单值槽位(排除 slot_cardinality=="set")的不同值 > 1:
    # 集合槽排除(新):兴趣爱好类多值共存,挑最新=制造错误答案
    # 变更语言检查(新):span 里有变更动词才许最新者胜
    if any(变更动词 in r.source_span for r in rel):
        strategy = 最新者胜(冲突阅读器)
    else:
        strategy = 矛盾并呈(矛盾阅读器)   # 裸分歧,近因不算数

# ── 路 6:有记录但无对可裁(admit_noop)──────────────────────
elif rel:  return 阅读器(全部retrieved)      # 不动任何东西(良性无操作)

# ── 路 7:零记录(no_records / 可选弃答守卫)─────────────────
else:
    if abstain_guard:  注记 = "记录层无该槽位的任何值;若历史确实未提及,请声明不可用而非猜测"
    return 阅读器(question + 注记, 全部retrieved)
```

## 1.5 裁决层逐行讲解——问历史/变化的路

```python
# ── 范围门 + 显式日期覆盖(新)───────────────────────────────
scope = extraction.query_temporal_scope
if 问题含具体历史日期(ISO 或 "May, 1986" 月名式):
    scope = "past_or_change"        # 确定性信号优先于 LLM 分类
if scope != "past_or_change": 走 1.4 的当前态路

# ── 链组装 ──────────────────────────────────────────────────
chain = [r for r in records if r.slot ≈ query.slot]   # 宽容槽位匹配(含包含关系)
chain.sort(key=日期键)   # 日期键 = 轮元数据 session_date,缺失时回退 stated_date

# ── 三种补全(治"最早状态排在检索 top-10 之外")──────────────
_resweep(值线索查询)     # "entity slot earlier previous before: 已知值…" 二次稠密检索,
                         # 优先合并早于已知最早态的轮
_sibling_sweep()         # 链记录同会话的邻座轮全部合并(真状态常在隔壁轮;零嵌入)
_extract_sweep()         # 识别扫描:代码做日期窗口过滤 → 抽取器语义识别
                         # (嵌入认不出"keto"是"diet",LLM 认得;链空时是从零建链的唯一机制)
# 合并规则:重抽后链不缩短→整体替换;缩短→并集吸收(永不丢已发现的状态)
# 所有扫描的抽取调用用 focus_q 钉死槽位(防在干扰窗口里漂移成别的槽)

# ── 点时刻路(dim4)──────────────────────────────────────────
pdate = 从问题解析的日期
valid = max(r for r in chain if r.日期 <= pdate)       # 区间算术:代码做,不留给阅读器
if valid is None:                                       # 问的日期早于全部已知态
    _extract_sweep(upto=pdate)                          # 时间约束的识别扫描
    仍无 → 兜底注记"记录起点晚于所问日期,答案可能是更早状态,请查原文"
else:
    注记 = f"于{pdate},{slot}为{valid.value}(录于{valid.日期},至{下次变更}未变)。
            这就是答案;不得声称该日期无信息"      # 命令式:治"区间推理拒绝"
    # (软化措辞版已被证伪:-6pp——阅读器服从性是资产)

# ── 轨迹路(dim5)──────────────────────────────────────────
if 链有 >=2 个去重后状态:                # 包含式去重:'vegan'/'fully vegan'算一态
    注记 = "该槽位的记忆链:值1(日期1) -> 值2(日期2) -> …;
            被问如何变化时,按序列出每个记录在案的状态"
```

# 三、现在还有什么不足

## 3.1 效果层面

1. **前提陷阱维仍是短板**:最优配置也只 21/53(40%)——反驳注记只治"旧值在题面"的子类,阅读器的前提顺从是更深的对齐问题
2. **T2(跨属性隐晦更新)对便宜抽取器仍超纲**:haiku 栈 T2 22.0%,升级到 sonnet 抽取(52.1%)才可解,但成本上升
3. **非时序冲突物种只做到"零伤害"**:错误信息型(佐证计数 dev 平)与条件绑定型的净胜均未实现——它们本质需要来源可信度与条件求解,不是时间机制
4. **STALE-Chain 残差 40% 是墙**:模型升档/提示词/QVF 三路线都救不动(6-11%),部分是证据不可达与生成噪声

## 3.2 边界层面(已实验确认、须如实写进论文)

5. **不叠加于强阅读器(文档 RAG)**:TempReason-raw 上 sonnet+QVF ≈ sonnet 直读;价值=让便宜阅读器追平强阅读器,iso-cost 优势只在有陷阱维的 STALE 系成立
6. **弱阅读器吃不动复杂裁决路**:新契约在 haiku 上 T1 -4pp(强阅读器无伤)——路由复杂度的代价按阅读器强度分摊,部署需按档裁剪
7. **成本**:输入 token ×3-11、延迟 ×2-3;条件调用门(-62%)尚未套用到新基准;组合格 52k tok/题

## 3.3 评审层面(3 位审稿人 3 分 borderline 的欠账)

8. **缺记忆系统基线**:Mem0 / Zep 未实测(写入时台账是内部代理);审稿人明确要求
9. **自建基准与方法假设同构**:生成器约束(逐字 span/严格递增日期/单值槽)正是抽取契约爱吃的形态——需对抗性 oblique split(状态非逐字陈述)与新种子冻结版确认集
10. **架构主张被先行工作占据**(HippoRAG/PAL/Chain of Condition):写作必须重构为问题主张("时序替换是需读取时查询条件化处理的独立失效类")
11. **"定律"措辞超出证据**:二因子律基于 2 个阅读器家族,应降格为"假设/观察"
12. 统计细节:一侧检验需标注;条目级聚类重报(已验证仍决定性:31胜1负 p≈10⁻⁸);错误解剖需标注协议与复标一致性

## 3.4 工程层面

13. LoCoMo/HoH 部分切片 n=50-400 偏小;LME 弃答子集未单独评
14. 判官是 LLM(跨家族复判 97.9% 一致已缓解,人工审计仅 100 条)
15. 运行器历史包袱(`--items` 缺省曾两次静默截断;prompted 条件命名误导已更正)
