## 〇、一分钟版本

**QVF 是什么**:长期对话记忆系统。写入侧把整库对话抽成六字段卡片(值/陈述日期/逐字锚点/替换边/属主/槽位类),按 `(属主, 槽位类)` 分组成状态链;读取侧每题走 聚焦 → 路由(四臂)→ 编译成 11 算子闭集 JSON 计划 → **纯 Python 执行** → 读者渲染。核心命题 `valid : S × Q → {0,1}`。

**目标**:ACL/NAACL 2027,距投稿 2–3 个月。

**当前诚实定位**:**合格的诊断/测量论文,不是方法创新论文**。三条候选技术创新已零成本全部证否,查新判 **0 条为新**(2 条已被 PODS 2007 与 Findings ACL 2025 占)。

**唯一抢不走的位置**:QVF 是唯一同时满足"**库自建(所以会错)**"和"**执行确定性(所以可单独测)**"的系统,因此是唯一能把端到端失败分解成"库的锅"还是"执行的锅"的**测量仪器**。首个读数:c₁ = 99.6% / c₂ = 46.2%。

### opus 建卡实验:**判据不可执行,本轮产物作废**(08-18 15:10 查实)

**先说判决:这一轮不能出任何 opus vs haiku 的结论。**不是因为跑得不够,是因为
两边不是同一个配方。

**查实的三件事**

1. **opus 卡片不空。**`wikiP108000-Q59200022` 有 **97 条 records**,其中
   `slot="employer"` 4 条,值序列与真值链**完全一致**。
2. **但 opus 卡片没有 `owner` / `slot_class` 两个字段**(haiku 的 P6 卡片两个都有)。
   这正是 `QVF_CARD_KEYS=1` 才会追加的 V4 目录提示词所产的两个键
   (`wt_qvf_prototype.py:308` — `base = CATALOG_PROMPT_V4 if _CARD_KEYS else CATALOG_PROMPT`)。
   **结论:opus 那一轮没带 `QVF_CARD_KEYS=1`,haiku 基线带了。**
3. **于是评测器把 opus 判了 0/8,而这个 0 是构造出来的。**
   `card_quality_eval.py:130` 按 `r.get("slot_class") == target_slot` 过滤;
   opus 记录里 `slot_class` 全是 `None`,池必然为 0,
   八行详情全部落 `failure_mode="zero_cards"`。
   **这个 0/8 不是测量结果,是字段名不匹配。**

**回落口径的诊断数(仅供定位,不作判决)**:把过滤改成 `slot_class or slot`,
同 8 个 uid 上 **opus 3/8 vs haiku 7/8**。但这仍然不是模型对比——opus 拿到的是
基底提示词,没有 V4 的 `slot_class` 闭集约束,所以它按自己的口径自由命名
(`upcoming_plans` / `recent_activities` / `habits` …),抽出 97 条 vs haiku 22 条。
它的失败也全是"过度收录"型:`language school in roppongi (english teaching job)`、
`new job (unspecified)`、`stanford university (research associate)`(值里混进职位)。

**连带作废一条旧记载**:本文档原写"opus 抽 94 张卡 vs haiku 22 张(4.3×)"并
把它当作模型差异的证据。**撤回。**那是 V4 vs 基底提示词的差异,模型只是其中一个变量。

**下游影响(比评测器更要紧)**:`slot_class` 是生产路径的一等字段——
`qvf_router._keyed_depth`(`qvf_router.py:259`)和
`complex_query_arm._select_pool_frozen`(`complex_query_arm.py:383`)都靠
`[r for r in recs if r.get("slot_class")]` 建键控组。**任何不带 `QVF_CARD_KEYS=1`
建出来的卡片库,进读取侧会整体掉出键控路径**,而且是静默回落,不报错。

**重跑前必须对齐的清单(否则再跑一次还是白跑)**
