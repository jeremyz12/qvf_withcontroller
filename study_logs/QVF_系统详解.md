# QVF 系统详解(2026-08-11 版)

> 目标读者:你自己。读完应能不看任何其他材料,向导师/审稿人完整讲清楚这套系统是什么、为什么长这样、每个数字从哪来。

---

## 0. 一句话与一个比喻

**QVF = 放在记忆系统与阅读器之间的"时序裁决层"**:不训练模型、不改检索,只做一件事——判断"这条记忆对这个问题是否有效",然后删除 / 保留 / 注记 / 反驳。

比喻:阅读器是法官,记忆是证据。RAG 只做了"把相关卷宗搬上桌"(相似度检索);QVF 是**书记员**——开庭前把过期的证据抽走、给有效证据贴上日期标签、发现原告引用过期条款时直接附一张纠正说明。法官还是那个法官,判决质量却完全不同。

## 1. 解决什么问题:时序状态选择

**定义**:同一属性随时间累积多个值(住址搬过三次、工作换过四家、球队转过五次),读取时必须按**查询的时间语义**选取或组合正确的状态。

四个子问题(基准里的四维一一对应):

| 子问题 | 问法 | 正确行为 | 基准维 |
|---|---|---|---|
| S1 当前态 | "现在住哪?" | 取最新,弃旧值 | dim1 |
| S2 点时刻 | "4 月 10 日那天住哪?" | 按日期做区间推理 | dim4 |
| S3 轨迹 | "住过哪些城市,顺序?" | 全链按序,一个不漏 | dim5 |
| S4 过时前提 | "既然住西雅图,推荐社区?" | 先纠前提再帮忙 | dim2 |

**明确排除**(不是我们的问题,论文里写清楚):错误信息冲突(本质是信源可信度)、条件共存(工作日咖啡/周末茶,不该裁决)、静态事实、弃答校准、时长/排序计算。

**为什么要先定义问题**:五个公开基准逐题实测"问题含量"——LoCoMo 对抗集 0%、LME 时间推理 45%、自建考场 100%(按构造)。含量决定了方法在哪该有效、在哪该中性;LME-TR 的"统计中性"拆开看是含题子集赢、超纲子集平——**考场必须按问题含量选**,这是自建 WikiState 的立论基础。

## 2. 概念核心:有效性是查询条件化的

同一条记忆"我住西雅图(2021)":

- 问"现在住哪" → 它是**必须防的过时噪声**;
- 问"2021 年住哪" → 它是**唯一正确答案**;
- 问"既然住西雅图…" → 它是**需要反驳的陷阱源**;
- 问"搬过几次家" → 它是**答案的组成部分**。

推论一:**防错 ≠ 删旧**。任何"清洗记忆库"的方案(Mem0 式写入时合并)必然杀死 S2/S3——这是 Mem0 在我们全部考场 20-41% 的结构性原因(时间线腐蚀)。
推论二:**裁决只能放在能看见问题的位置**。写入时不知道将来会被怎么问,所以哪怕抽取前移了(wt),**裁决永远发生在读取时**——wt-v3 的"写入时"指的是抽取,不是裁决。

推论三(实验钉死):**相似度与有效性在时序问题上反相关**。旧状态与问题最相似(陷阱命中率 93-100%),oracle 注入证明检索做到完美直读陷阱维仍只有 8-24%——这是与 RAG 的本质分界。

## 3. 系统全景:一门、两器、一路由

```
                        问题
                          │
                    [mini 聚焦调用]  ~0.2k tok
                    槽位/时间语义/预设值
                          │
              ┌───────────┼───────────────┐
     非时序问题│      浅链(<3态)│        深链(≥3态)│
          ┌───▼───┐   ┌───▼────┐    ┌────▼────┐
          │ 直通   │   │ 读取时  │    │ 写入时   │
          │ (门)  │   │ QVF(rt)│    │ wt-v3   │
          └───┬───┘   └───┬────┘    └────┬────┘
              └───────────┼──────────────┘
                          ▼
                       阅读器
```

三条路各自的赢区由实验划定(见 §7 证据地图),路由信号全部免费:时间语义来自本来就要做的聚焦调用,链深来自卡片库查表。

## 4. 读取时 QVF(rt):检索后即插即用

五段流水线,每次提问全部现场执行:

1. **检索**:稠密 top-10(不改动宿主系统的检索);
2. **抽取(LLM)**:把检索到的记忆现场抽成档案卡——实体/槽位/值/**逐字锚点**(必须原文子串,代码可核对,防幻觉)/关系(replacement 指向被替换的记录);
3. **裁决(~150 行 Python,零 token)**:按问题分路,分支优先级:
   - 不可变槽位(生日/兄弟数)→ 永不"取最新",并呈+佐证计数;
   - 终止声明("不健身了")→ 删被终止状态,声明本身是答案;
   - ≥2 个条件(工作日/周末)→ 共存不删;
   - 矛盾对(无更新语言)→ 并呈给专用矛盾读者,"近因不是证据";
   - 替换对 → 删旧轮,**先过时间检查**(被删轮必须严格早于替换轮;HoH 实测缺这行 100%→74%);
   - 题面引用旧值 → 追加反驳注记;
   - 历史路(问那天/问轨迹)→ **永不删除**,区间算术选态 + 三种补全扫描找漏网状态;
4. **投喂(减法原则)**:只删被证实过时的,其余全保留+注记——数学性质:未检索到旧状态时 QVF 什么都不动,结构上不可能伤害已答对的题;
5. **阅读器**正常答题。

**赢区**:浅二态更新(LME-KU 82.1% 全场最佳)、时点算术(WikiState 时点 82-100%)。
**弱点**:每题付抽取费(输入 3-11× 直读);轨迹题受检索天花板压制(全链进 top-10 仅 55%)。

## 5. 写入时 wt-v3:档案卡库(旗舰)

### 5.1 写入阶段(每条记忆一次,摊销)

会话入库时由 haiku 批量抽卡入库。实测成本:普通条目(35-50 会话)21.3k in + 7.7k out ≈ $0.06;超长条目(600 句)225k in ≈ $0.34,自动分批建卡(超上下文对半递归,今天上线的基建)。**这笔钱 ≈ 全文方案一次查询,之后永久复用**;真实部署是增量的:每新会话 ~0.5k。

### 5.2 读取阶段(每题三步,1.6-1.8k tok = 直读价位)

1. mini 聚焦(0.2k):问题 → 实体/槽位/时间语义/预设值。提示词强制**具体属性名**("职位"),禁抽象词("职业发展")——v3 教训:抽象槽位匹配不到任何卡;
2. **纯代码裁决(0 token)**:
   - **连通分量选链**:对卡片库做并查集——replacement 关系边 + 槽位模糊匹配(下划线/连字符归一)连边;只有明确的替换关系才把卡连进同一条链,闲聊卡天然被隔离在孤立分量里;
   - **槽位主导评分**选最佳分量:`4×槽位命中 + min(关系边,3)`——v3.1 的反直觉教训:关系边数量在累加型链(职业)上是**反向信号**(新职位不"替换"旧职位,反而干扰闲聊里"辞了A去B"带替换边),所以槽位命中主导、关系边封顶;
   - 选好链后同 rt 分路:链尾/区间算术/全链/反驳注记;
3. 阅读器作答(读者提示 = 修正框定验证版:对话誊录、日常口吻、注记权威)。

### 5.3 为什么轨迹被它修好

直读/rt 的轨迹证据靠检索碰运气(55% 全链覆盖);卡片库**按构造全链在场**——每个状态入库时就有卡,拼链是查表。这是轨迹维 0-29% → 69-100% 的机制解释,也是"档案卡库不是 RAG 索引"的最好例证:索引为找到,卡库为裁决。

### 5.4 版本史(每一步都有配对证据)

| 版本 | 内容 | 结局 |
|---|---|---|
| v1 | 建卡+紧凑裁决 | 卡片污染:WikiState 60.1%,时点倒退 → 演进 |
| v2 | 名字相似聚类选链 | dev 横跳 10→8→7/12,不可靠 → 废弃 |
| v3.1 | 关系边 ×2 加权 | 反向奖励污染 → 撤销 |
| **v3** | 连通分量+槽位主导+禁抽象 | dev 冻结后 test 与全部新域零改动 → **现行** |
| (基建) | 分批建卡/对半重试(08-11) | 不改评分逻辑,超长条目可入库 |

已知未修缺陷:**目录抽取覆盖率**(个别会话漏卡 → P54 原卷 dim1 95→79 回落)。修复=逐会话强制分诊契约,会产生 v4、需按 dev/test 规程重验,列为下一次方法迭代。

## 6. 路由器(整合版,进行中)

规则(原则先行,不做数据调参):

```
scope=unclear 且无预设值        → 直通(调用门)
scope=trajectory/point 且链深≥2 → wt
scope=current 且链深≥3          → wt
其余                            → rt
```

链深 = 卡片库中聚焦槽位所在**最佳连通分量**的不同取值数(v1.1 起与 wt 裁决同款逻辑,一个信号两处用)。

v1 首跑(13 考场 2325 问组合评测):**直读 62.5% → 路由 76.6%**;chain-212 上 82.1% **反超最优单臂**(路由能逐题择优);浅链正确回落 rt;LoCoMo 负税收回大半。已知问题与修法:深链探针 v1 太粗(槽位词汇分散时误判浅链)→ v1.1 换分量深度;六考场缺 rt 臂造成降级伪影 → rt 补臂在跑。

### 7.2 外部对照

- **Mem0**:真实域 20/30/26%,比不装还差;死因=时间线腐蚀(0 次 UPDATE,记忆膨胀 1.4×,日期按摄入日解析);
- **sonnet-5 直读**:三域 55/71/84,被 haiku+wt 反超 6-32pp 且每题更贵($0.008 vs $0.003);轨迹与 haiku 逐字持平——升档修不了轨迹;
- **gpt-5-mini**:直读陷阱 7%(前提采纳最重),提示救到 79%,轨迹仍 0——两定律跨厂商;
- **前沿 agentic(CC/Codex)**:考试框定下 94.7-100% 是天花板,但 8-14k tok/题($0.05-0.12);且对弱模型是双刃剑(600 句/条目时 haiku agentic 崩到 10%)。QVF 生态位=**单遍预算内逼近天花板**。

### 7.3 方法论发现(附带贡献)

- **框定效应**:旧评测框定(JSON 板砖+弃答条款)压低一切单遍成绩 11-25pp;前沿模型部署框定税 28pp,税率∝证据埋深。全部自建数字已重定标(协议 v2),三道反作弊检查(同修正应用于所有臂/增量仍双显著/外部基准未动);
- **措辞敏感性**:轨迹题措辞与域错位时,测的是措辞不是能力(P551 同批条目直读 0→91%);已立措辞对齐规程,w2 卷为正式引用版。

## 9. 边界(如实清单)

1. 饱和区不该装(gpt 干净版 0胜10负);
2. 前沿 agentic 考试框定下全饱和 → 判别域=弱中档读者/受限上下文/部署态;
3. 浅二态:wt 失效(rt/提示够用);
4. 超纲域:wt 交负税 → 调用门是部署必需品;
5. 非时序冲突:零伤害无净胜(定义排除);
6. wt 简单维偶发漏卡(覆盖率,v4 待修)。

## 10. FAQ(被问过/会被问的)

**Q: 和 RAG 什么区别?** 直读基线就是 RAG;区别=检索与投喂之间的按题裁决层。oracle 实验:检索完美直读陷阱仍 8-24%,加裁决 87.3%。相似度与有效性在时序上反相关。
**Q: 和 Mem0/Zep 什么区别?** Mem0 写入时合并丢时间线(实测三域全灭);Zep 建时序图但无查询条件化分路裁决——最近的系统近亲,related work 必写。
**Q: 为什么不直接用强模型?** sonnet 直读被 haiku+wt 反超且更贵;轨迹升档零增益。前沿 agentic 能到天花板但 40× 价钱,且弱模型 agentic 会反噬。
**Q: 改了协议成绩变好,可信吗?** 同一修正应用于所有臂;增量新协议下仍双显著;外部基准数字未动;新种子三度复现。
**Q: wt-v3 是最终版吗?** 是写入时线的冻结旗舰,不是系统最终版;最终形态=路由器整合(进行中),因为 wt 有实测负区。
