# W4 设计文档:WikiState-QA —— 真实数据的时序状态记忆基准(2026-08-07)

## 动机(对齐反馈)

反馈原话:"解决的领域有限,效果也不是百分百好……找更加真实的、适合的数据,让方法在该领域有更好的结果。"
诊断:STALE 家族是合成/半合成的助手记忆场景;需要一个 **真实数据为底、时序状态裁决为任务本体、金答案可机械验证** 的域,且该域天然偏向 QVF 的强项(链组装、区间算术、写入时建库)而非其短板(开放式行为)。

## WikiState-QA 构造方案

**条目 = 一个实体的一条属性链**(P39 任职 / P108 雇主 / P54 队籍 / P551 居住地 / P26 配偶,链长 ≥3 优先):
1. 经 Wikidata API 拉取实体 JSON,机械抽取 (value, start, end) 序列,校验区间无重叠、严格递增(确定性验证器,同 STALE-Chain 谱系)
2. **记忆化改写**:把每个状态渲染成一条带日期的第一人称/助理视角"会话记录"(如秘书备忘口吻:"[1876-05-01] 陛下今日加冕印度女皇");干扰会话复用 STALE 干草堆协议。渲染用 opus 一次性生成,**逐字锚点验证器**保证值与日期不被改写
3. 四问维照搬 chain 协议:当前态(以条目内最晚日期为"今天")/ 中间态陷阱 / 点时刻 / 轨迹——金答案全部由限定符机械导出,**零人工标注**

## 污染控制(此域的关键设计,STALE 没有的问题)

Wikidata 名人在预训练语料里,模型可能不看记忆就答对。三道闸:
1. **参数可答过滤(核心)**:每个候选条目先跑一个"无记忆对照"——读者不给任何历史直接答四问;参数知识能答对任一问的条目**整条丢弃**。留下的条目 = 只能靠提供的记忆作答
2. 偏选长尾实体(链完整但知名度低:地方议员、小联盟球员、企业中层——SPARQL 按 sitelinks 数升序抽样)
3. 实体化名变体(可选强化):把实体名替换为化名,彻底切断参数通路,同时保留真实链结构

## 为什么该域偏向 QVF

- 状态链长(政治人物任职常 5-10 段)→ 链组装与区间算术的价值随链长放大;提示式方法在长链上的"脑内时间线"负担线性增长
- 写入时架构的天然主场:实体档案一次建卡,服务无限查询(与 W3 原型直接衔接)
- 真实数据的噪声形态(同日多职、区间开放、任职重叠)构成新的裁决物种,能长出新规则——研究纵深比合成数据深

## 试点计划(下一步,可立即执行)

1. SPARQL 拉 200 个低知名度、P39/P108 链长≥3 的实体 → 机械验证 → 取前 60
2. 参数可答过滤(haiku 无记忆对照,四问全错才保留)→ 目标净 40-50 条目
3. opus 记忆化渲染 + 逐字/日期验证器 → WikiState-60
4. 三方基线(修正框定):直读 / 政策提示 / QVF(读取时+写入时双架构)
5. 判官沿用 opus + 机械金答案(此域判官几乎退化为字符串/日期核对,可信度更高)

预算估计:渲染 60 条目 ≈ 60 次 opus 调用;基线四臂 ≈ 每臂 200-240 问 haiku。一晚可完成。
