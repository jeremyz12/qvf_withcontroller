## 零、一段话版本

QVF 处理长期对话记忆的一个具体失效:**当同一件事在不同时间被说过不同的值,系统答题时会取错版本、或者取到了全部版本仍然算错**。它的做法是把"这条记忆过没过时"从记忆自身的属性改写成 **(记忆, 问题) 的二元函数**,然后在读取侧把问题**编译成可执行的查询计划**,由 **Python 代码**而不是答题模型完成版本选择与历史聚合。

在 418 道机械金答案的**单算子聚合题**上,这条流水线相对"检索 + 模型心算"值 **+35.4pp**(簇稳健 p=4.14e-17)。但审计查明这 +35.4pp 是**管线级**差值而非"谁做算术"的隔离值,其中约 9pp 来自对照臂看不到全部证据;而在**算子复合**题上,该机制被最朴素的稠密检索直读**反超 17.9pp**。

论文因此定位为 **Diagnostic + Formalization paper**(诊断 + 形式化),不是 System paper。

# A · QVF 究竟要解决什么问题

## A1 声称要解决的问题

**核心观察**:长期对话记忆系统的主要失效模式不是遗忘,而是**在多版本状态并存时选错版本**。

**形式化命题**:
```
valid : S × Q → {0,1}
```
一条记忆是否有效,**不是它自身的属性,而是 (记忆, 问题) 这一对的函数**。同一条"我住在上海"记录:

| 问题 | 该取什么 |
|---|---|
| 我现在住哪 | 最新值 |
| 我 2022 年住哪 | 那个时点的历史值 |
| 我搬过几次家 | 全部值 |

既有系统普遍把"过时"当成记忆的内在属性——要么物理删除旧值(Mem0 附录算法 1 的 UPDATE 置换 / DELETE),要么保留历史但读取时把带日期区间的事实整包交答题模型自行取舍(Zep、Engram、MAGMA、A-TMA)。

## A2 实际通过方法和实验解决的问题

**声称 vs 实证对照表**(只认 `results/` 的对照实验与台账判决行):

| 声称 | 有无对应实验 | 评级 |
|---|---|---|
| 编译-执行相对直接读取,在单算子聚合题上大幅更好 | 有,418 题同题配对、簇=uid | ✅ **本项目最硬的实证之一** |
| 6 原语可将 11 算子表为深度 ≤3 宏,宏执行与平面执行逐字节等价 | 有,纯符号零 LLM,可独立复算 | ✅ **另一条最硬的**(但覆盖面须如实报,见 D) |
| `JOIN_T∘WINDOW` 是该原语集表达不了的客观边界 | 有判定脚本,**但是手写白名单非穷举** | ⚠️ 结论可能对,证据力打折 |
| 预注册自我证伪审计协议 | 有,126 项耦合审计 + 1107 条盲写改写 + 零改动新域 | ✅ 三支柱中唯一"审稿人拒绝不掉"的 |
| P 是**最小**完备基 | **无**。全库无"5 原语不足"的证明或穷举 | ❌ **"最小"已撤回** |
| +35.4pp 是"代码执行"的隔离价值 | **无**。能隔离该变量的第三臂全库不存在 | ❌ 改述为管线级对照 |
| 11 算子编译执行路径装在被评测的整合系统里 | **无**。`qvf_router.py` 不 import `complex_query_arm` | ❌ 须明写"机制测量在隔离条件下" |

**A1 与 A2 的落差,三条**:

1. **范围落差**:声称"算子级隔离量化",实做是管线级对照——两臂**同时**在写入侧(原文 vs 结构化卡片)与读取侧(模型心算 vs 代码执行)不同。
2. **归因落差**:整合系统 5061 题的 +10.61pp 里,**+5.64pp 由一段提示词拿到**(纯提示词回落规则 65.94% @1275 tok vs 直读 60.30% @1904 tok),全部结构化机制净 **+4.21pp**(簇自助 95% CI[+1.39, +7.16])。
3. **部署落差**:产生头条主张的代码路径不在整合系统里,而路由规则 `qvf_router.py:375-376` 还把事件算术题判给直读,注释原文"卡片裁决无增益"(缓解:该正则在生产题面命中率仅 1.3%)。

## A3 这个问题在领域中的位置

技术线:**长期对话记忆 → 时序状态维护 → 读取端的查询结构化**。QVF 卡在最后一环,而这一环上游、同侧都已有人,下游没有。

| 位置 | 谁 | 状态 |
|---|---|---|
| **上游(已做完)** | Engram、Graph-Native Bitemporal Store、Zep/Graphiti | "保留取代历史"都做了,读取侧仍是检索 + LLM 心算 |
| **同范式先到** | **Prog-TQA**(LREC-COLING 2024,KoPL 12 时序算子 + 符号执行)、TReMu(Findings ACL 2025)、TGMS(13 闭集时态算子 + 更强的声明验证器) | **编译-执行不是新方法** |
| **同思想先到** | A-TMA(附录 A.7 Table 5:Full 0.883 vs 宿主 0.825) | "按问题时序意图选状态视图"的**隔离消融首创权不归 QVF** |
| **最危险的近邻** | **APEX-MEM**(ACL 2026 主会,Amazon) | 属性图 + LLM 临场生成只读 GraphSQL(SELECT/JOIN/AGGREGATE/TEMPORAL),**执行本身也是确定性代码** |
| **下游** | 无 | |
| **方法先例** | TimeQA(NeurIPS 2021 D&B) | 用 Wikidata 限定符机械导金答案,WikiState 应引它为先例 |

**结论**:不是开辟新问题(2025–26 至少 6 个独立团队同时在攻),不是老问题换方法,而是 **"两个已存在的东西第一次接在一起 + 一个新的形式化角度"**。QVF 占的是**一个接口位置**和**两件方法学产物**。

**相对 APEX-MEM 目前守得住的三条**:①结构化查询来自**固定闭集算子词表 + 生成前独立类型检查器**,而非 LLM 在 ReAct 循环里临场生成 SQL;②**答前 `premise_check`**——APEX-MEM 的消解规则逐字是 "the agent selects the most recent valid entry",只处理多版本、不处理假前提;③**管线级路由**——它 §4 无任何问题分类,40 步预算对所有题型平摊。

**已被它打掉的一条动机**:"LLM 生成的查询不可靠"基本不成立了(其 SQL 执行成功率 Sonnet 97.6% / GPT-5 93.4% / Haiku 95.4%,失败自恢复 87%)。

## A4 若无 QVF,已有方法具体卡在哪里

**域外证据(方向,不是幅度)**:

| 来源 | 数字 | ⚠️ 引用纪律 |
|---|---|---|
| **APEX-MEM** Table 1 Full-Context 行 | 同一模型、同一份**完整**证据:open-domain **92.70%** vs temporal **71.88%**,落差 **20.82pp** | **最干净的一条**:证据齐全而时序题仍不行,检索侧解释被排除。这是别人家的数据,比自证更有力 |
| Graph-Native Bitemporal Store | 跨会话计数 **30% R@10 / 0% R@1**,并明言"检索本身无法回答" | 可用 |
| QO-Bench | 相似度检索交集 **6.0%** vs 抽取到结构化 + 代码执行 **≈51%** | 可用 |
| TimelineQA | 85.1% → **4.3%** 随证据数崩塌 | **⚠️ 措辞必须改**:§5.4 原文 "with a **perfect retriever**",论文自己的解释是 "the hardness of dealing with large input tables";§5.1 "even as we set the max input length to 1024, 20% of the input episodes are truncated"(测试集 20.40%)。**它是 reader 侧容量失效,不是检索崩塌** |

**项目自有的机制证据**:

- **能力买不到**:四档模型稠密直读 38% → 57%(opus-5),而"问变化全程"(轨迹维)**四档全零**。
- **容量不解决结构**:整库全塞上下文作 oracle,总分 66.7%,但**陷阱维仍塌到 49%**。
- **最具说服力的单例**:直读检索到全部 3 个雇主、日期一个不错,答"变了 3 次"(正确 2)。**证据满分,算术失败**——这类错误提示词修不了。

**同页必须写的反向诚实**:S8 未见组合里 `WINDOW_2ANCHOR∘COUNT`(**正是计数题型**)直读臂 **21/23 = 91.3%**,与"检索式读取在聚合上系统性失败"直接冲突,根因未诊断。

## A5 一句话:真实问题意识

摘要写的是"记忆有效性是 (记忆, 问题) 的函数"。但那是**脚手架**——新定位的三支柱已不再把这条形式化列为贡献。

真正在问的是:

> **"当记忆系统必须做算术时,把算术交给代码这件事,到底值多少分、在什么条件下值、条件不满足时倒亏多少?"**

前两问答了。**第三问也已测出(倒亏 12.6–72pp),但至今没写进论文。**不写,支柱三就是一次没通过自己检验的自我表扬。

# C · 相比已有方法的真实创新点

## C1 改变了哪个环节

**改变的是且仅是一个环节:证据包 → 答案之间,原本由答题模型承担的"版本选择 + 历史算术"这一步。**

既有系统读取侧三段:检索 → 组装证据包 → 交答题 LLM 自行取舍。QVF 在第二、三段之间插入两步:`C: Q → P`(单次调用编译成 11 算子闭集的严格 JSON 计划)与 `E(p, S)`(纯 Python 执行,零 token)。

**必须同时说清的三件事**:①**写入侧不是 QVF 改的环节**(追加式、双时态、`supersedes` 边,Zep/Engram/GNBMS 都已这么做,"唯一保时间线"的旧措辞**已作废**);②**路由不是新环节而是新的一层**(A-TMA §4.4 已有规则式查询画像四类);③**被改的那个环节在整合系统里覆盖 0/5511 题**。

## C2 引入了什么

1. **算子条件化卫生过滤 H** —— 本项目最被低估、最像真发现的一条。
2. **六原语代数 + 独立类型检查器 + 逐字节对拍护栏**。
3. **双时态增量索引 + 四条完整性不变量**(12,500 次随机插入零失败;`chain_depth` O(1) / `asof` O(log))。
4. **学习路由 + ε 结构性下界诊断**:`â(x) = argmax_a [p̂_a(x) − λ·c_a]`,并证明主口径证书**结构性不可达**(ε 渐近下界 **9.27% > 目标 5%**;oracle-gap 8.96pp 中 **97.4% 是排序误差**)。
5. **组合泛化 split** —— 最有转移价值,也自伤最深。

## C3 为什么这个变化可能有效(机制)

代码执行在三件事上与模型心算不同:**确定性**(同输入同输出)、**可组合**(计数之上再取最长)、**与链长无关的正确性**(不因证据变多而退化)。项目自己的产物层证据:用冻结的 `execute_plan` 零 LLM 重跑 418 题,**Python 结论行本身已含 gold 的题 331/418 = 79.2%**,端到端 83.7%;`change_count` 与 `count_before` 两个题型上**读者的净贡献为零**。"聚合由代码完成"在产物层面属实,不是话术。

## C4 创新的性质:是不是"多加了一个限定的提示词"

**一半对**:面向模型的那一层(建卡契约 / 编译 / 读者 / 聚焦)确实全是提示词,无新模型结构、无新学习算法。

**一半错**:**裁决不在提示词里**——`count_changes` / `longest` / `count_before` 是 Python;路由要遍历卡片库算键控深度,提示词看不见库。三个非提示词对象:六原语完备基(可独立复算的符号事实)、带 (ε,δ) 证书的路由、双时态索引四不变量。

**最硬的反证**:"只有提示词"的版本**被造出来过**——四臂里的提示词臂就是它,全量测过。

**但三处必须承认的漏水**:(a) 代码的产出以**可被无视的自然语言**交回模型;(b) 写入侧的"硬契约"只是提示词且未强制;(c) **承载核心创新声称的那条代码路径没装进被评测的整合系统**,而整合系统最大的一臂(49.5% 流量)就是一段提示词 `_WARN_INSTRUCTION`,它在 LME-KU 上以 **92.3% @2.7k token** 击败了当时的完整 QVF(78.2% @64.9k)——**1/24 的成本**。

## C5 与最相关方法的分界句

| 对照 | 分界句 | 它反过来能反驳什么 |
|---|---|---|
| **APEX-MEM**(ACL 2026 主会) | 它由 LLM 在 ReAct 循环中**临场生成只读 SQL**;QVF 的结构化查询来自**固定闭集算子词表 + 生成前独立类型检查器**,且先经管线级路由 | ①"闭集"的代价有实测:S8 未见组合闭集算子**低于不做任何结构化的直读 18–21pp**,SQL 没有这个天花板;②"生成前校验"拒绝后**不重试**,带来的是**沉默的降级**;③"管线级路由"被自家 ε 结构性不可达结果削弱 |
| **TGMS** | 它吃**预加载图数据**、算子面向**图拓扑**、**无路由**;QVF 算子面向槽位状态演化,库从对话原文在线抽取并带逐字锚点 | 它算子数(13)更多、闭集程度相同,**且其声明验证器(重执行核对)比 QVF 的"逐条日期引用"更强**。在"LLM 只规划、代码执行、并验证"这条范式上,**QVF 不是第一个,而且是较弱的那个** |
| **Prog-TQA**(LREC-COLING 2024) | 它在**给定的时序 KG** 上符号执行 KoPL 程序;QVF 的库由写入侧契约从对话原文自建 | 范式 2024 年已在主流会议发表,**算子名逐个撞**(FilterFirst/FilterLast、FilterBefore/After、FilterByTimePoint、**GetDuration**……)。**"时长计算"不可再称独有;编译-执行范式不可作为新意的任何一部分** |

**措辞纪律**:`join_at_change` 不称独有(CronQuestions ACL 2021 复杂桶已含 time join);"端到端"必须限定为"**从对话原文到答案**"(EXAQT 占了无限定用法)。

## C 判决:新意 **中偏弱**

| 对象 | 判决 | 理由 |
|---|---|---|

# D · 实验是否足够支持核心结论

## D1 核心结论(逐条)

1. 编译-执行相对检索-心算,在单算子聚合题上大幅更好(+35.4pp)
2. 6 原语可将 11 算子表为深度 ≤3 的宏,宏执行与平面执行逐字节等价
3. 一套预注册自我证伪审计协议是可执行的,并完整报告其失败
4. 适用边界:状态空间可被预定义闭集覆盖 + 存在可追踪的结构化状态变化

## D3 只能间接支持的

- `valid : S×Q` 形式化的 **+54.5pp**(32.0% vs 86.5%):对照物是**我方自行"忠实重写"的竞品策略**,保真度无第三方核验,且差值里含全部架构差异。

## D4 缺失的关键 baseline(最难堪的一栏)

1. **全上下文直读**。现有对照臂被 top-10 检索瓶颈限制,**必需证据完整率仅 71.1%**。补一次是零风险、几十美元的实验;**不补,审稿人会替你补**。

## D5 缺失的消融

**能隔离"谁做算术"的第三臂全库不存在**:同卡片库、同证据包、去掉 Python 结论行,让读者自己在卡片链上数。全库检索 `no_derived / evidence_only` 零命中。**没有它,+35.4pp 只能叫管线级对照。**

另:**变异测试证明 `PICK` 原语在全部 713 行护栏上是死覆盖**——`current` / `first_last` 分支不读求值器算出的 `node["rec"]`,而从共享 `base_chain` 重算;`current`+`first_last`+`trajectory` = **237/713 = 33.2% 的分母在结构上必然相等**,与原语实现是否正确无关。

## D6 数据集 / 指标 / 实验设置偏向

- 三份主基准全部自建自植;唯一非植入的 LoCoMo 上系统本体为负。
- 13 线难度标定面板**跨三个不同题集**拼成(n=80 / 228 / 208),拉到同题后**名次改变**。
- 在售系统对照**用错了比较基准**:LangMem 只跑 80 题,而"裸直读 48.6"取自另一个 208 题切分;**在 LangMem 那 80 题上直读只有 36.25%**。故"三个在售系统装了反而更差"**必须停用**。
- STALE 全量 +11.3pp 里,**82% 来自自撰的 dim2**;dim1(才是 STALE 原任务)只有 +6.25pp,dim3 是 −0.25pp。

## D7 提升是否足够显著

**旗舰在三重扰动下全部存活**:去重(5511→5061)、Holm(m=59)、簇校正。S5 +35.4pp 的 p 从 4.14e-17 到 Holm 1.08e-15;P108-ext 3.58e-18 → 2.08e-16;两张 LTT 证书去重后仍成立。

**但**:全库**零多重比较校正**,Holm 后 12 项跌为不显著;负结果未施加簇校正而正结果施加了;S8 那轮的预注册主判据在 **n=61 / 30 簇下不可裁决**(W/L/T=6/3/52,p=0.508,簇自助 CI 跨零)。

# E · 可能的反例(每条指向一个具体依赖)

1. **算子复合。** 依赖"聚合题可被单算子覆盖"。S8 未见组合 67 题:代数臂 49.3% / 平面臂 52.2% / **直读臂 70.1%**(token 仅 36%);`WINDOW_2ANCHOR∘COUNT` 直读 **91.3%** vs 平面 30.4%。61 题持出组合集三臂 16.4 / 18.0 / 21.3%,与 S5 的 83.73% 差 **60pp**。**有效区间是"单算子聚合",不是"聚合"。**
2. **"哪份工作干得最久",而答案是当前这份。** 依赖闭区间口径。该形态在题集里覆盖率 **0/103**;接回真实 end 后 **55/92 的 gold 被推翻**。**这是"基准与实现同源"最干净的一个实例。**
3. **更强的 baseline:全上下文直读。** 依赖"对照臂拿不到全部证据"。必需证据完整的 297 题上 Δ 从 +35.4 缩到 **+26.3pp**;`first_vs_last` 在证据完整层上直读 98.8% **反超**编译 95.0%(不显著,即两臂不可区分)。
4. **闭集外槽位。** 依赖七类闭集覆盖。零改动新域 P69(就读学校)编译臂 **21.3%** vs 直读 **60.0%**(−38.7pp);三卷合计 **55.07% vs 67.63%**(−12.56pp)。
5. **浅链 + 更强的答题模型。** 依赖"链深 ≥2 才有可裁决的多版本"。LME-KU 上卡片臂 **64.1%** < 直读 78.2% < 提示词臂 **82.1%**。
6. **多说话人 / 状态属主不是"我"。** 依赖单用户假设。LoCoMo-full 66.2% < 直读 69.4%,根因是说话人库未键控。
7. **提问里没有 `(Today is X.)` 前缀。** 依赖时点锚从问题文本传入,而真实部署中这个通道不存在,回落路径逻辑上循环。
8. **一条消息同时宣告两个状态 / 乱序披露。** 依赖"每条 chain 记录恰对应 1 个 turn"与顺序无关性。B4 乱序测试 seq==shuf 同答率 **77.8% < 95%** 门槛,判据触发。
9. **写入侧出错时读取侧没有察觉能力。** 依赖建卡质量。**70.0% CI[52.1, 87.9]** 的写入侧,配一个被指令禁止怀疑证据的读取侧。
10. **真实语料没有逐字植入。** 依赖"答案是原文的合法 span"。TimelineQA 自己承认其 atomic 82.6% 偏高正是因为 "answers are always a valid span in the input"——**QVF 的逐字锚点契约在同样的构造下被同样抬高**。而按契约字面定义,实测逐字满足率是 **89.55%**,不是文档写的 98.6%。
11. **增量写入。** 依赖离线批处理。逐会话抽取实测**贵 7.89×**、丢 **44.2% 的替换边**。

## 附:一句话与三句话(答辩用,审计后口径)

**一句话**:
> 我们把"记忆过没过时"从记忆的属性改写成 (记忆, 问题) 的函数,并首次对"由代码而非答题模型完成版本选择与历史聚合"这条流水线做同题配对的精确定价——在单算子聚合题上值 +35.4pp(簇稳健 p=4.14e-17),而在算子复合题上它被最朴素的稠密检索反超 17.9pp,这个边界我们照实报告。

**三句话**:
> 一、**读取侧**:现有记忆系统到"把证据交给模型"就停了,我们把问题编译成闭集算子的可执行计划,版本选择、计数、拼链全由代码算——直读检索到全部三个雇主还是会答"变了 3 次"(正确是 2),这类错误提示词修不了。
> 二、**一个可陈述的数学对象**:11 算子的 6 原语完备基,宏执行与平面执行 **874 次逐字节比较、11/11 算子覆盖、零不等价**,纯符号可独立复算;我们同时报告一个该原语集表达不了的组合,以及该护栏在三处对原语实现**没有辨别力**的位置。
> 三、**方法学**:我们把"系统是不是被基准特调"做成了可执行的预注册审计——它抓到了自家一个让成绩虚高 6 分的 bug、一处让头条归因写反的样本框污染、以及一条"15 卷 5511 题"实为 13 组 5061 题的规模错报;我们改低了数字,而机制主张的方向在去重、Holm 校正与簇校正三重扰动下全部存活。
