### A2-注1:+35.4pp 不是"算子级隔离",是管线级对照

`scripts/wsc_direct_arm.py` 文件头逐字写明直读臂是:会话原文装配成记忆条 → 稠密检索 top-10(`TOP_K = 10`,**第 60 行**)→ 一次 haiku 读者调用。编译臂读的是写入侧 LLM 另跑一遍抽出的六字段卡片库,再编译计划、纯 Python 执行、渲染证据包。

两臂**同时**在写入侧(原文 vs 结构化卡片)和读取侧(模型心算 vs 代码执行)不同。这是**范式对照**,不是算子隔离。真正的算子级隔离需要第三臂:同一份卡片库、同一份证据包、去掉代码算出的结论行。全库检索零命中——**这一臂不存在**。

而项目自己的数据表明这一臂会改变结论:`results/wsc_s8_report_20260816.md` §三根因诊断记录,`WINDOW_2ANCHOR∘COUNT` 崩到 1/23 = 4.3% 的原因是"编译对、执行对、**读者看不到锚点证据就拒答**"——即**证据包渲染方式**在支配准确率。渲染能一手把 4.3% 变成 18.8%,那么把 +35.4pp 整包记在"代码而非模型做算术"的账上,缺一次隔离。

> ### 判决:支柱一的 headline 措辞"**首次把它隔离到算子层并精确定价**"名不副实。它精确定价的是"卡片 + 编译 + 执行 + 渲染"整条流水线相对"检索 + 心算"的差。审稿人问一句"你怎么知道这 35.4pp 不是卡片抽取带来的?"——现有实验答不上来,只有 T1 的间接旁证。

### A2-注2:摘要里的机制归因句,算在被自己判定污染的样本框上(**本节重算**)

见〇节统一替换框。四个数 `49 / 36 / 29 / 4` **逐一精确命中"排除 P39 后的 314 题框"**;定稿 418 框重算为 **59 / 50 / 39 / 22**,`first_vs_last` 差值 **+17.1pp**;P39 那 104 题里 `first_vs_last` 是编译臂**表现最好**的题型(18 胜 0 负)。

> ### 判决:项目诚实地把头条数字从 89.81% 下修到 83.73%,并把这次下修写成方法学资产;但**支撑机制归因的那一列数字没有跟着重算**。在定稿框上,"不需算术的题型几乎无增益"是假的。这句话现在写在**摘要草稿里**,且偏差方向恰好利于作者。

## A3 该问题在领域中的位置

依据 `QVF_related_work_verified_20260814.md`(30 篇逐篇核实 + 08-16 ACL 2026 补扫)。

技术线:长期对话记忆 → 时序状态维护 → **读取端的查询结构化**。QVF 卡在最后一环,而这一环上游、下游、同侧都已有人。

- **上游**:Engram(2606.09900)、Graph-Native Bitemporal Store(2607.26520)、Zep/Graphiti。"保留取代历史"已做完,读取侧仍是检索 + LLM 心算。
- **同侧(同范式先到)**:Prog-TQA(LREC-COLING 2024,KoPL 12 算子)、TReMu(Findings of ACL 2025)、TGMS(2607.10265,13 闭集时态算子 + 双重验证)。措辞纪律已明令"编译-执行范式:不称首创"。
- **同侧(同思想先到)**:A-TMA(2607.01935)已有"按问题时序意图选状态视图"的**隔离消融**(附录 A.7 Table 5:Full 0.883 vs 宿主 0.825)。核实档原文:"**该思想的首创权与价值量化不归我们**"。
- **最危险的近邻**:APEX-MEM(**ACL 2026 主会**,2026.acl-long.749)——属性图 + GraphSQL,支持 SELECT/JOIN/AGGREGATE/TEMPORAL,**执行本身是确定性代码**。核实档判定其危险度"高于 A-TMA"。QVF 与其分野只剩三条:闭集算子词表 vs LLM 临场生成 SQL、生成前合法性校验、管线级路由 + 端到端 token 成本报告。
- **下游**:无。
- **方法先例**:TimeQA(NeurIPS 2021 D&B)用 P580/P582/P585 限定符机械导金答案——WikiState 应引它为先例。

结论:不是"开辟新问题"(≥6 个独立团队在 2025–2026 同时进攻),不是"老问题换方法"(编译-执行不是新方法),而是 **"两个已存在的东西第一次接在一起 + 一个新的形式化角度"**。

> ### 判决:QVF 不占任何单点首创,它占的是**一个接口位置**和**两件方法学产物**。问题在于 APEX-MEM 已在 ACL 2026 主会上从另一侧占了大半。QVF 相对它的增量听起来像工程约束,不像科学发现。**当前三支柱里没有一条是冲着 APEX-MEM 写的。**

## B 节最危险的一条

> ### R1:整个方法论的地基——"写入侧能把对话变成可信事实表"——只在一种语料上被测量过,而那种语料是把答案逐字植进去的。

**证据链三步**:

1. **植入是代码行为,不是巧合。** 渲染提示词逐字要求 "**EXACTLY ONE** turn must state ... the span must contain that **EXACT** name **verbatim**",并"**do not mention any other** `{noun}` values";`validate_state()` 三条断言逐条把关;渲染三次不过直接 `FAILED render, skipped`。
2. **在这个条件下,写入侧核心契约是恒真的。** Methods §1 定义 1 把"σ 为出处锚点——约束为会话原文的逐字连续子串"写成硬约束。**在一个把目标字符串逐字植入的语料上,这条约束不构成任何检验。**
3. **而即便如此,写入侧只恢复 70% 的链。** 台账 B6:n=3 重建 **78.0 / 68.0 / 64.0**,均值 **70.0%,95% CI [52.1%, 87.9%]**;固定 temperature=0 后 σ 只从 7.21pp 降到 3.85pp(**降 46.5%,未过预注册减半线,主假设被否定**),项目自结论"**剩余为契约/抽取过程本身的固有不确定性**"。

**为什么这条比 LoCoMo 告负更伤**:LoCoMo 可用"适用边界"框住;few-shot 同构已被 T4 拆除;新域失败已撤回并修复——**这三条都有处置**。R1 **没有处置,而且当前无法处置**:三份主基准全部自建自植,唯一非植入的 LoCoMo 上系统本体是负的。它是**乘性**的,一次打穿三支柱。

**一句话版本(给审稿人预演)**:

> "你们的写入侧契约要求逐字锚点,而你们的语料是把答案逐字植进去生成的;在这个最有利的条件下,你们的抽取仍然只恢复 70% 的状态链,95% 置信下界 52%。请问在没有植入的语料上,这个数是多少?"

**目前唯一诚实的回答是:不知道,没测过。**

# C · 相比已有方法的真实创新点

> 立场:凡项目文档里的"我们做到了 X",一律回到 `results/` 与源码去看那件事是否真的发生、发生在系统的哪一部分、以及在多大的题面范围内发生。

## C1 改变了已有方法的哪个环节

**改变的是且仅是一个环节:证据包 → 答案之间,原本由答题模型承担的"版本选择 + 历史算术"这一步。**

既有系统读取侧三段:检索 → 组装证据包 → 交答题 LLM 自行取舍。核实档对四家的描述一致停在第三段:Zep「把 "FACT (Date range: from - to)" 整包交答题 LLM 自行取舍」;Engram「四信号混合检索交 LLM 心算」;MAGMA「取回子图后交 LLM 自由推理」;A-TMA「打标证据仍交 LLM 直接作答」。

QVF 在第二段与第三段之间插入两步:`C: Q → P`(单次调用编译成 11 算子闭集的严格 JSON 计划)与 `E(p, S)`(纯 Python 执行,零 token)。

**必须同时说清楚的三件事,否则 C1 是虚报:**

1. **写入侧不是 QVF 改的环节。** 追加式、双时态、`supersedes` 边、保留被取代值——Zep / Engram / GNBMS / Semantic XPath 都已这么做,项目早前"唯一保时间线"的措辞**已作废**。
2. **路由不是新插入的环节,是新插入的一层。** A-TMA §4.4 已有规则式查询画像四类。核实档原话:"**该思想的首创权与价值量化不归我们**"。SituatedQA(EMNLP 2021)是更早的同构设定。
3. **被改的那个环节,在整合系统里只覆盖 35% 的题,而 11 算子编译执行路径覆盖 0%。** 见 C4 第 (4) 条。

## C2 引入了什么新的建模/数据处理/评估方式

### (1) 算子条件化卫生过滤 H —— 本项目最被低估、也最像真发现的一条

```
H(pool, op) = pool                                     若 op ∉ COUNT_OPS
            = dedup_session(drop_datephrase(pool))     若 op ∈ COUNT_OPS
COUNT_OPS = {count_changes, count_before, first_last, longest}
```

理由非平凡:**一张碎卡对点查无害,对计数是 ±1 的直接错误——所以去噪必须条件在下游算子上,全局清洗会改变点查语义**。与 DocETL(PVLDB 18(9))正交且更精细。**当前三支柱框架里它一个字都没有**,是定位上的一处真实错配。

### (2) 六原语代数 + 独立类型检查器 + 逐字节对拍护栏

`P = {SELECT, TAGSET, WINDOW, PICK, ASOF, AGG}`;11 算子全部表为深度 ≤3 的 P-表达式;AST 为 pydantic 三层显式嵌套,深度 ≤3 由结构 + `check_expr` 双重强制,解释器约 90 行。`JOIN_T(e₁,e₂) ≡ ASOF(e₂, at=e₁)` 被吸收,省一个原语。

### (3) 双时态增量索引 + 四条完整性不变量

I1 替换边无环 / I2 任一时刻每键至多一个活跃值 / I3 链内日期单调(自纠为弱单调)/ I4 边端点存在;12,500 次插入 + 400 次顺序无关性对照零失败;`chain_depth` O(1)、`asof` O(log 链长),n=1e5 时 p50 9.54ms / 8.84ms。**自带诚实边界:11 算子中只有这 2 个亚线性。**

### (4) 学习路由 + ε 结构性下界诊断

λ=0.5 档 +1.94pp 且 −51.6% token;去数据集身份特征后 +2.23pp / −50.3%。真正可移植的是**诊断方法**:`ε_ub(n) ≈ 9.27% + 0.305/√n`,`p_inf = 9.27% > 目标 5%` ⇒ **不存在有限校准集使证书可发**;oracle-gap 8.96pp 分解为"重校准可修 0.24pp / 排序误差 8.73pp = 97.4%"。终裁已降为诊断性局限,该降级是对的。

### (5) 评估侧:组合泛化 split —— 最有转移价值,也自伤最深

S8 把 held-out 单位从"题目实例"改为**算子组合**;金答案由代码机械导出、独立校验器 121/121 复核、抽 21 题手推零不吻合。**这个评估设计本身值得单独发表——而它产出的正是本节最不利的证据。**

### (6) 其余属"照搬有先例"

WikiState 金答案导出法(TimeQA 先例);L1/L2/L3 难度分层(TempReason);"逐条日期引用"(核实档红旗第 3 条明令:**表述为轻量证据纪律,不作验证机制贡献**)。

## C3 这个变化为什么可能有效(机制)

**机制假设**:检索式读取在聚合/历史类问题上的失效,失效点不在检索(证据常常是全的),而在**取回证据之后的算术与版本裁决**。

**支持该机制的证据(按强度排序):**

1. **增益的分布是机制的显影,不是总分**——**【本条按对抗核查替换】** 在 **418 题定稿框**上:`change_count` +49.5pp(净胜 59)、`longest_tenure` +42.7pp(50)、`count_before` +32.4pp(39)、`first_vs_last` **+17.1pp(22)**。分布形状与"增益随算术负担单调增强"同形。
   **但强形式("不需算术题型无增益")被本项目定稿数据否定,C3 不得再以"分布形状与机制假设同形"作为强于总分的证据。**
2. **定性单例**:直读检索到全部 3 个雇主、日期一个不错,答"变了 3 次"(正确 2)。
3. **域外三证支持方向**(不是 +35.4pp 这个幅度)。

**反对该机制成立的证据(必须同页写):**

- **确定性执行的正确性不传导到答案。** S8 的 `WINDOW_2ANCHOR∘COUNT` 上,逐题验证编译计划**完全正确**、纯代码执行**完全正确**,读者仍拒答,代数臂 **1/23 = 4.3%**,而**直读臂 21/23 = 91.3%**。
- **空证据时管线是 fail-open 的**:P69 编译臂 21.3% 反而低于直读 60.0%,空证据率 70.7%。
- **编译失败不重试**:`IllFormed` 直接降级为空证据。

**结论**:机制解释站得住,但成立条件比论文当前措辞窄得多——**它成立于"问题落在算子表内、卡片链建对了、证据包渲染齐了"三个条件同时满足时**;任何一个破,系统的表现不是"退化到直读",而是**低于直读**。

## C4 创新性质:面向模型那一层是不是全是提示词?

**结论先给:不是全部,但"面向模型的每一个接口"确实全是提示词;代码只存在于接口与接口之间,并且在两端都没有强制力。**

### (1) 面向模型的那一层

### (3) 代码与提示词的边界处,三处漏水

**漏水一:代码的输出以自然语言祈使句交回给模型。** `derived` 行原文包括 `"... This IS the answer."`、`"Mention ONLY these items ..."`、`"IMPORTANT: the message presupposes {v}, which is OUTDATED ..."`。**计算是代码做的,执行是靠说服模型的。** S8 的 4.3% 就是它无视了。精确说法应是"**由代码完成计算,由提示词请求模型采纳该计算**"——而这个差别恰是 TGMS(带重执行验证器)与 QVF 的分野方向,**朝对我们不利的一侧**。

**漏水二:写入侧那条"硬约束"在代码里不存在。** Methods Algorithm 1 第 2 步写 `assert card.σ ⊑ text_j  # 逐字子串校验,违约丢弃`。全仓检索写入路径:逐字子串要求**只以 `CATALOG_PROMPT` Rule 1 的英文句子存在**,写入路径没有任何 assert / 过滤 / 丢弃逻辑。事后审计测得 98.6% 逐字出自原文——**即约 1.4% 违约的卡片被照常入库**。这是**声称与实现的直接落差**,定稿前必须改。

**漏水三:写入侧质量本身是提示词级的。** 归档库对源链精确匹配 76.88%;契约期望质量 70.0%,CI [52.1%, 87.9%]。**整条读取侧的确定性,建立在一个 ±20pp 摆动的提示词产物之上。**

### (4) 最伤的一条:被当作创新的那条代码路径,不在整合系统里

- `scripts/qvf_router.py` **全文不 import `complex_query_arm`**(全仓检索确认)。
- 整合系统的 `wt` 臂由 `wt_qvf_prototype.read_phase` 产出,其纯代码裁决段(`:441-560`)只有 `point_in_time` / `trajectory` / `current` 三个分支——**`count_changes` / `longest` / `count_before` / `first_last` / `join_at_change` / `tag_*` 六类算子一个都没有**。
- 四臂实测分派(5511 题):`prompt 2729 / wt 1949 / direct 440 / rt 393`。即 **11 算子编译执行路径覆盖整合系统 0/5511 题**;`prompt + direct = 57.5%` 的题目**完全没有代码侧版本选择**。
- 更糟的是 `scripts/qvf_router.py:376-377`:

```python
if _GATE_V2 and is_event_arith(question, bench, qid):
    return "direct", None   # 事件算术(时长/计数):卡片裁决无增益,直读
```

**整合系统对"时长/计数"这类题的处置是判给直读臂,理由写在注释里是"卡片裁决无增益"。** 而 S5 的 +35.4pp,其构成正是 change_count / longest / count_before 三类。(缓解:该正则在生产题面上仅命中 1.3%,实际受影响题量小——但**规则本身写死的判断与论文头条主张相反**。)

- 并列佐证:**整合系统最大的一臂就是一段提示词。** `_WARN_INSTRUCTION` 承担 2729/5511 = **49.5%** 的流量,并在两个考场上以 1/24–1/33 的成本击败当时的完整 QVF 系统:LME-KU **92.3% @2.7k vs 78.2% @64.9k**;LME-TR **70.7% @2.7k vs 40.6% @89k**。

**C4 的如实回答**:面向模型那一层全是提示词;代码在中间层是真的、量也不小;但 (a) 代码的产出以可被无视的自然语言交回模型,(b) 写入侧的"硬契约"只是提示词且未强制,(c) **承载核心创新声称的那条代码路径没有装进被评测的整合系统,路由规则甚至把它最擅长的题型判给了直读**。

## C5 与最相关方法的差异

### 近邻一:APEX-MEM(ACL 2026 主会) —— 当前最危险

**分界句**:APEX-MEM 由 LLM 在 ReAct 循环中**临场生成只读 SQL**(GraphSQL);QVF 的结构化查询来自**固定闭集算子词表 + 生成前独立类型检查器**,且先经管线级路由。

**三处可被反驳点**:① "闭集"的代价有实测数字——S8 未见组合代数 49.3% / 平面 52.2% / **直读 70.1%**,闭集算子在组合外**低于不做任何结构化的直读 18–21pp**,SQL 没有这个天花板;② "生成前校验"拒绝后**不重试**,带来的不是正确性保证而是**沉默的降级**;③ "管线级路由"被自家结果削弱(ε 结构性不可发,已降为诊断性局限)。

**残余守得住的一句**:APEX-MEM 无答前 `premise_check`,QVF 的 `premise_check` 在读取计划内、生成之前由代码判定。这是**管线位置**上的真差异。

### 近邻二:TGMS(2607.10265) —— 形态最同构

**分界句**:TGMS 吃**预加载图数据**、算子面向**图拓扑**、**无路由**;QVF 算子面向**槽位状态演化**,事实库从**多会话对话原文**在线抽取并带逐字锚点。

**最危险的反驳**:TGMS 算子数(13)多于 QVF(11),闭集程度相同,**且其声明验证器(重执行核对)比 QVF 的"逐条日期引用"更强**。**在"LLM 只规划、代码执行、并验证"这条范式上,QVF 不是第一个,而且是较弱的那个。**

### 近邻三:Prog-TQA(LREC-COLING 2024)

**分界句**:Prog-TQA 在**给定的时序知识图谱**上符号执行 KoPL 程序(12 算子);QVF 的库由写入侧契约从对话原文自建。**反驳**:范式 2024 年已在主流会议发表,算子数量级相同。**QVF 在这条范式上没有范式级新意,只有域的迁移**,而域迁移那一半靠的是一个提示词,质量 CI [52.1%, 87.9%]。

### 次级近邻与措辞纪律

- **A-TMA**:其 Full 0.883 vs 宿主 0.825 的隔离消融先例意味着"按问题时序意图选状态视图"的首创权不归 QVF。
- **CronQuestions(ACL 2021)** 复杂桶含 time join ⇒ **`join_at_change` 不得称独有**。
- **EXAQT(CIKM 2021)** 自称 first end-to-end ⇒ QVF 用"端到端"必须限定为"**从对话原文到答案**"。
- **PRA(COLM 2026 Workshop poster,非主会)**:作者自陈不处理 historical queries / temporal reasoning。**这不是"击败竞争对手",是把定义展开成了一个数字。**(核查记录:复算 `results/wiki_pra_newest_dense.jsonl`,228 题 73 判对 = 32.02%;同口径 test-208 = **31.73%**,差 0.29pp,**+54.5pp 成立**——本节唯一一处尝试证伪却证伪失败的数字。)
- **时态 KGQA 一族**:安全的独有差异点仅 `premise_check` / `count_changes` / `longest` / `tag_filter` / `tag_trend`;**不安全**:time join、"该族依赖结构化查询"的笼统概括。补充自伤:`tag_filter` / `tag_trend` 依赖写入侧 `value_tags`,而开放标签的替代方案主判据**被否定**(格闭包召回 4.5%)。

## C 节判决

> ### 支柱一(机制诊断)—— **新意 中**

被测现象不是新的,隔离消融思路 A-TMA 已有先例;新的是**测量精度与测量对象**。这是一次干净的**首次精确定价**,不是发现。

> ### 支柱二(六原语最小完备基)—— **新意 弱**

命题是**相对自家 11 算子集合**的构造性完备性。数学含量低:证明 = 11 行宏定义表 + 90 行解释器;逐字节等价 347/347 证明的是"同一语义实现了两遍且行为一致",不是一个定理。Prog-TQA(12)、TGMS(13)算子数相当,只是没人去做最小基约简——"没人做过"与"值得做"之间还差一个论证。

**加分项**:`JOIN_T∘WINDOW` 被机械脚本判定不可表达并如实上报,是**独立于设计者意图的客观边界**;`|P|` 零膨胀的精确措辞纪律也做到了(不可说"零代码":dev 轮 2 给 WINDOW 加 7 个可选界字段、AGG 加 `count_elements`,约 60 行)。

**决定性扣分**:代数臂**不能主张更准**——未见组合 49.3% < 平面 52.2%;渲染器修复后在 61 题持出集上仍只有 **21.3%**,**且该轮未跑直读对照臂**。

> ### 支柱三(预注册自我证伪审计协议)—— **新意 中**

三支柱里**最难被 C5 那几篇反驳的一条**:核实过的 30 篇里无第二家发布自家代码耦合清单,无第二家做判据先行的零改动跨域测试。产出也是真的。

**扣分项**:① 预注册本身不是新概念;② 终裁裁决⑤同时判定"耦合审计的存在证明系统脆弱"**成立**;③ 方法学贡献在 ACL 主会计价历来偏低。

> ### 总判决:**新意 中偏弱** —— 真实、可核查,但窄;不构成范式级贡献

**按现有证据能守住的最强表述**(比 §四摘要草稿再收一格):

> 在状态空间可被预定义闭集覆盖、且问题落在预先枚举的算子范围内时,把版本选择与历史聚合从答题模型移交给确定性代码,可带来 +35.4pp 的机制隔离增益(簇稳健 p=4.14e-17),**增益随算术负担单调增强**(+49.5 / +42.7 / +32.4 / +17.1pp);我们同时报告该优势在算子组合外(S8 未见组合:直读 70.1% > 结构化两臂 49–52%)与真实对话基准上(LoCoMo-full 66.2% < 69.4%)不复现,并给出该算子族的最小表示基与其一个结构性不可表达的组合。
