## 一、这是一个什么项目

**一句话**:让 AI 助手在记住你很多年之后,还能在"你现在住哪 / 你 2022 年住哪 / 你一共搬过几次家"之间**选对该用哪一版记忆**。

**问题的正式形态**:一条记忆有没有过期,不是这条记忆自身的属性,而是 **(记忆, 问题) 这一对的函数**——
```
valid : S × Q → {0,1}
```
同一条"我住墨尔本"的旧记录,对"我现在住哪"是污染,对"我 2022 年住哪"是唯一正确证据,对"我搬过几次家"是必要成分。因此任何在**写入时**就给记忆盖上"过期"图章的方案(删掉旧值、永远取最新),在定义上就只能答对三类问题中的一类。

**系统名**:QVF(Query-conditioned Validity Filtering,查询条件化有效性过滤)。定位句:**写入时把个人记忆结构化为带时间与语义标签的事实表,读取时把问题编译成对这张表的查询计划——时序有效性只是这套算子族的第一个算子。**

**产出目标**:一篇 ACL/EMNLP 长文(系统 + 资源 + 实证)。

## 二、思路是怎么来的(来源)

**起点是一个反直觉的观察**:长期对话记忆的主要失效模式**不是遗忘,是记得太多、选错版本**。两个实测锚点制造了最初的张力——

1. 把整个记忆库塞进上下文(不检索、全给模型看),总分尚可(66.7%),但"陷阱题"(问题预设了一个已过期的状态)反而塌到 49% ——**证据全在眼前也没用**,说明缺口不在检索。
2. 换更强的模型:四档模型直读从 38% 爬到 57%,但"问变化全程"这一维**四档全零**——说明缺口也不在能力。

不在容量、不在能力,那就在**结构**。这条推理产生了核心命题(有效性是二元函数),后续所有机制都是它的推论。

**需求不是自己发明的,有三重外部背书**:LongMemEval(ICLR 2025)原生就设了"知识更新"题类;2026 年 5-8 月有四个独立团队的近邻工作扑向同一问题(STALE、取最新策略、A-TMA、StateAuditor);反向佐证是 2026 年最新的跨会话个性化基准 CAPA 仍把用户偏好建模为**静态**("(a_i,r_i) remains stable" 是其原文)——"状态会过时"是这个赛道的系统性盲区。

**数据来源**:
- **WikiState(自建,主战场)**:八字口径"**事实真实、载体合成**"。事实与日期取自 Wikidata 真实人物的状态链(带 P580 起始/P582 结束/P585 时点限定符,方法先例是 TimeQA);对话是把这些事实渲染进多会话第一人称聊天。**金答案由代码从时间限定符机械导出,零人工裁量**——作者没有出题的裁量权。
- **公开基准(客场)**:LoCoMo(ACL 2024)、LongMemEval(ICLR 2025)、STALE(2026 预印本)。
- **新域测试集(泛化检验,自建)**:P69 就读学校 / P1303 演奏乐器 / P26 配偶,同一管线抓取渲染。

## 三、技术方案(五个环节)

**环节 1 · 写入侧:批量建卡。** 新会话入库时整库打包一次,交给最便宜的模型(haiku)按固定契约抽取。每张"卡"六个字段:**值、陈述日期、原文逐字锚点、替换关系、属于谁、哪类属性**,外加语义标签。两条硬约束:锚点必须是会话原文的**逐字连续子串**(可被代码机械校验);连任/换届这类近同值必须独立成卡。
*为什么在写入时做*:每条记忆一生只被读一遍是理论下界。答题时再抽取(我们的另一条臂)实测每题 19-43k token,一题就超过整库建档全款(约 29k token ≈ 6 美分)。

**环节 2 · 存储:每用户一张微型时态事实表。** 卡片库是 JSON 里的记录数组,本质是 (属主, 属性类, 值, 时间, 证据, 替换) 六元组表——结构上几乎就是 Wikidata 的"陈述 + 时间限定符"。这一步的意义:**记忆一旦成表,裁决就能交给代码**。

**环节 3 · 读取侧:问题编译成查询计划。** 一次小模型调用(~0.3k token)把自然语言问题编译成严格 JSON 计划,11 个算子:取最新 / 按日期取值 / 拼全程 / 纠过时前提 / 计数 / 最长 / 时点前 / 首末 / 标签过滤 / 标签趋势 / 跨槽位 join。
*为什么是编译不是问答*:难度升级涨在**计划长度**上,不涨在 token 上——S1 到 S7 每题同价(~1.7-2k token)。

**环节 4 · 执行:零 token 的代码裁决。** 计划由普通 Python 在事实表上执行(分组、日期区间过滤、排序拼链、按标签上卷),产出证据包交给读者模型作答,并强制逐条带日期引用。**LLM 不做任何计数或日期算术。**

**环节 5 · 门与路由:四臂调度。** 每题按两个信号分派:问题类型(时序?算术?)与**库形态**(键控深度=这件事在库里有几个历史值;整库是否皆浅)。四条臂:无关/算术→直读;整库皆浅→把裁决规则写成提示词的便宜臂;历史厚→查事实表;残余→现场抽取。
*为什么多臂*:每条臂单独全量测过,各有一半地形显著更差。成本控制也在这:最贵臂占比从 65% 压到 6.6%,靠的是**让题绕开贵路**,不是把贵路砍瘦(五把工程刀全部弃用,证明砍不动)。

**近两日新增的三件(旗标门控,默认关,冻结行为逐字节不变)**:
- **学习路由**:`argmax_a [ p̂_a(x) − λ·c_a ]`,λ 由 Learn-then-Test 校准并给出 (ε,δ) 证书。
- **开放槽位规范化 + fail-closed**:槽位匹配从"手写词表判死"升级为"字符串归一 + 嵌入规范化(词表保留否决权)";证据为空时不再让读者硬猜。
- **6 原语时序代数**:SELECT/TAGSET/WINDOW/PICK/ASOF/AGG,11 个算子全部表示为深度 ≤3 的宏。

## 四、实验方法学(七条纪律)

1. **机械金答案**:金答案由代码从 Wikidata 时间限定符导出,零人工。
2. **防背题 + 防泄露**:模型裸答能对的条目全删;建卡/答题/判官三条路径做过五路代码审计,含 **421 库 / 25,619 卡 / 59,481 项字段**的机械对照,98.6% 逐字命中会话原文,零字段"只见于金结构不见于会话"。
3. **dev/test 隔离 + 迭代额度**:规则只在 dev 上迭代,**每个契约最多 3 轮,用完即封笔**(有过第 3 轮被三表否决、就地封笔回退的记录)。
4. **同题配对 + 弃刀线**:任何改动做同题 A/B,配对符号检验报 p 值;降本改动掉超过 1 分即弃(五把刀全灭,如实入档)。
5. **单一判官协议**:opus 判官、对方法全盲、13 种方法同一段代码;独立复判一致率 20/20。
6. **诚实入档**:负结果、反例、样本-全量差全部进台账。
7. **预注册**:近期所有泛化实验的判据都**先于跑数写死在档案里**,包括"掉到多少就撤回哪句声称"。

### 机制的隔离价值

| 机制 | 隔离测量 |
|---|---|
| 查询条件化(vs 查询盲"永远取最新") | **+54.5pp**(32.0 → 86.5) |
| 代码执行聚合(vs 模型自算) | **+31.8pp**(56.1 → 87.9,p=6.9e-19) |
| 学习路由(vs 手写阈值) | **+1.94pp 且省 51.6% token**;去掉数据集身份特征后 +2.23pp / 省 50.3% |
| 开放槽位 + fail-closed(闭集外域) | **21.3% → 60.0%**,旧域全量回归还 +1.91pp |

### 成本

- 建档:每库约 29k token ≈ **6 美分**,一次性、离线、可批处理五折。
- 答题边际:全系统均值 5.3k token/题;WikiState 域约 2.1k ≈ **$0.0027/题**。
- 回本点:对现场抽取第 1 题回本;对 sonnet 直读约 13 题回本。
- 同预算主张:便宜模型 + 结构($0.003/题拿 86-92%)胜过贵四倍的旗舰直读($0.012/题拿 57.0%)。

### 可信度证据

- 五路泄露审计全部 CLEAN(59,481 项字段机械对照)。
- 新域测试的裸答对照:186 题 × 2 模型 = 372 份裸答,**0 份判对**。
- 判官独立复判 20/20 一致。
- 代数宏与平面执行**逐字节等价 347/347**(现场零信任复跑)。
- 编译器可换成本地开源模型:qwen3:8b **零微调** 与 haiku 一致 **369/369 = 100%**;1107 条盲写改写上复验 99.91%。

### 泛化(近两日的重头戏)

- **改写鲁棒**:1107 条盲写改写,模板膨胀量 ≤0.3pp(预注册线 8pp)——编译成绩不依赖题面模板。
- **新域(系统一行不改)**:闭集内 P26 的四类时序题 **95-100%**(纠前提维 90.5% 甚至高于旧域参考 64.2%);闭集外 P69 修复后 60.0%。
- **代码耦合审计**:126 项手写制品逐项定性(原则性 40 / 领域适配 29 / 考场特化 57)。

## 六、现在的不足(诚实清单)

### A. 已被实测证伪、正式撤回的声称

- **"键控机制可泛化"已撤回**,降格为"闭集内成立"。证据:闭集内 78.7% vs 闭集外 21.3%,差 57.4pp,超过预注册的 15pp 线。修复后闭集外回到 60.0%,但主判据("新域整体 ≥ 旧域 −10pp 且无题型 <50%")**至今不成立**。
- **"代数臂更准"被否定**:未见组合上 49.3%,反低于平面臂 52.2%。代数只能主张**表达力更强**(平面臂结构性不可表达率 77.6%),不能主张更准。

### B. 结构性弱点(修复路线已知,尚未完成)

1. **七类槽位闭集**是最大软肋。真实的个人状态是开放词表(健康、订阅、宠物、饮食),闭集外的状态要么漏掉、要么落到最贵的臂。开放槽位规范化只修了读取侧的匹配,**写入侧的闭集本身还在**。
2. **fail-closed 只达标 1/3 题型**:"降级不作恶"成立了,但"臂答必不劣于直读"在首末/最长两型上不成立(84<96、60<76),原因是救援回来的证据池混了错类记录。
3. **证据包渲染缺陷**:双锚窗组合上编译对、执行对,但渲染器没把锚点记录本身放进证据包,读者拒答(1/23)。修复路径明确,但重测须重新预注册(题集已揭盲)。
4. **乱序到达语义有洞**:考场按时间顺序喂库,真人会今天回忆十年前的事。当前代码只按日期重排,替换边和相邻去重会静默算错。**正在跑的压力子集就是测这个。**
5. **口径双侧手工同步的指控未正面回应**:出题器与执行器对"计数怎么算、边界算不算"的约定是同一双手写的,`point_in_time` 的边界情形甚至被出题器提前剔除、从未受检。**正在跑的边界子集用独立实现的金答案来分辨这一条。**

### C. 与真实部署的差距

- **载体全合成**:系统从没见过真人对话。真人会说"我在考虑搬去墨尔本"(计划不是事实)、会开玩笑、会撤回。曾有过"巴黎旅行被抽成居住状态"的翻车,那是真实语言复杂度的预告片。
- **规模**:考场库是 37-67 个会话,真实使用以年计;大库下的检索与键深统计没压过力。
- **单用户假设**:owner 判定针对助手-用户二人对话,家庭共用场景未验证。
- **语言**:人称与事件算术的识别仍有英文/中文的手写模式,其他语言会漏检。

### D. 工程与统计的已知缺口

- 学习路由的次级证书**切分敏感**(三种子六次验证挂了两次),宣称强度已下调为聚类稳健界;主口径证书结构性发不出(最小可发证 ε≈9.9%)。
- 判官调用未落盘 token 用量,判官侧成本只能估算。
- S8 组合题集规格未满:`JOIN_T∘WINDOW` 只有 1 题,而且它是"现有原语覆盖新组合"论证的**真实反例**(现有原语表达不了)。

## 七、下一步队列

1. **边界/乱序压力子集**(进行中):用只读形式语义文档的**独立金答案**对拍执行器,分辨"口径是否为双侧手工同步";乱序入库 vs 顺序入库同答率。
2. **写入侧开放槽位**:把七类闭集从建卡契约里拆掉,下游按槽位字符串本身分组。
3. **渲染器修复 + 重新预注册重测**(代数臂的真实上限)。
4. **QVF-Compiler 蒸馏**:用前三项产出的多样性数据在本地 GPU 微调小模型,吃掉 few-shot 与槽位规范化,发布权重。先测量后训练,测量集永不入训。
