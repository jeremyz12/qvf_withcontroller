## 疑问记录

### Q1 · 写入时是不是固定去找"职业变化"?哪怕没提到也要看?
**回答要点**:不固定。契约原文是 `Catalog EVERY personal-state fact (residence, job, devices, plans, memberships, habits, providers, ...)`——括号里是举例不是清单,且 Rule 5 明确"Skip small talk with no state content. Do not invent facts",没提到就不建卡。
**实测佐证**:样本库 44 张卡里 employer 仅 3 张;其余是蜘蛛植物、白噪音机、心理治疗、外卖 app 等,模型自由写的槽位名有 `plants_owned` / `phone_case` / `food_delivery_app_used` 等。
**但直觉命中真问题**:15 个 slot_class 里 9 个是 `other:*`,**23/44 = 52% 的卡片落在七类闭集之外**;闭集外在下游是二等公民。
**触发改动**:无代码改动,但该数据成为闭集拆除设计稿的核心论据。

### Q2 · 说白了是不是就多加了个限定的提示词?
**回答要点**:一半对——面向模型的那一层(建卡契约/编译/读者/聚焦)确实全是提示词,无新模型结构、无新学习算法。一半错——**裁决不在提示词里**:`count_changes` / `longest` / `count_before` 是 Python;路由要遍历卡片库算键控深度,提示词看不见库。
**最硬反证**:"只有提示词"的版本**被造出来过**——四条臂里的提示词臂就是它,全量测过,只在"整库皆浅"时够用;某次门放太宽,44 道题误派进去,整卷回撤约 2 分。
**三个非提示词对象**:六原语完备基(逐字节等价 347/347)、带 (ε,δ) 证书的路由、双时态索引四不变量。
**触发改动**:无。但该问答被写入 QVF_system_and_claims_20260816.md 的对外话术。

### Q3 · 卡片槽是要做什么的?
**回答要点**:槽是**分组键**,回答"这两条记录是不是同一件事"。`(属主, 槽位类)` 是时态事实表的主键;没有它,"最新值""某天的值""变了几次""纠过时前提"四种操作全部无法定义。
**⚠️ 触发的发现(不在任何审计清单上)**:同一张表暴露 `device` 深度 7、`other:hobby` 深度 10——**这些是累积不是替换**(买充电宝不代表手机没了)。而卡片里早有 `slot_cardinality` 字段(single/set)正是为此设计,grep 确认它**在抽取时被填、在存储里在,但 complex_query_arm.py 与 qvf_router.py 里一次都没被消费**。
**触发改动**:已写入"顺序不变抽取"任务书,要求新抽取层明确填准 single/set;消费与否留后续。

### Q4 · 现在的流程是什么?能举个例子吗?
**回答要点**:用 `wikiP108011_s5a` 走完六步真实链路(问题→计划→证据包→结论行→回答→判官),证据包只有 3 行、成本 1824 in/107 out ≈ 2k token / 6.2 秒。关键:**"2922 天""哪个最长"是 Python 算的,模型只负责说人话**。
**⚠️ 触发的发现 + 自我更正**:证据包显示日期是 `[1970] [1976] [1984]` **只有年份**,而真实链是 1970-01-01 / 1976-03-01 / 1984-07-01。执行器用年粒度算得 Shell **2922 天**(正好 8 年),边界测试的独立实现用精确日期算得 **3044 天**,差 122 天正是 3 月 1 日到 7 月 1 日。**根因是日期粒度,不是我在第 1 步说的"区间开闭"——该处更正已当场说明。**
**影响**:argmax 类题稳(Shell 两种算法都最长),但**数值不稳**;若有题直接问"我在 Shell 干了多久"会答一个假精确的数字。
**触发改动**:入"边界语义待明确";成为三个创新提案中"日期区间传播"的直接依据。

### Q5 · 用户兴趣动态变化(上一题问职业、下一题问饮食)能调整吗?
**回答要点**:机制上**完全免费**——每题独立走"聚焦→路由→编译",**无任何跨查询状态**(无用户画像、无当前话题)。实测佐证:同一个库 135 题,分派出现 prompt / wt / direct 三种,由该题槽位的键控深度驱动。
**但质量随话题跳变**:职业在闭集内(全功能),饮食落 `other:diet`,键控深度为 0/None → 降级到 prompt/direct。
**判断**:不建议做跨查询适应(无状态是可复现性的保证);该投的是**写入侧闭集拆除**。
**触发改动**:**产出 study_logs/QVF_openslot_writeside_design.md 设计稿**(三层设计 + 四条预注册判据 + 三个难点对策)。

### Q6 · 论文要发表的话,创新点真的还强吗?
**回答要点**:核心更强(S5 定稿 +35.4pp 簇稳健 p=4.14e-17)、外围几乎全线失败(近两天约四条预注册判据被自己证伪)。结论:论文须从"功能丰富的系统"收窄为"一个被测到极限的机制 + 一套会证伪自己的方法"。
**关键判断**:今天所有失败的溯源**全都指向写入侧**,剩余 2-3 个月该投写入侧可靠性而非再做扩展。
**触发改动**:产出 QVF_system_and_claims_20260816.md(六条可声明 / 六条不可声明)。

### Q7 · 能在哪些方面添加确实的算法或结构上的创新?
**回答要点**:给出三个提案(按下注顺序)——①顺序不变抽取(有可证性质);②共识抽取 + 每卡置信度(最算法化);③日期粒度区间传播(最理论)。三条**全部在写入侧或写入-读取接口**,刻意不再往读取侧堆功能。
**触发改动**:①已实现并跑完,**方案被否决**(成本 7.89×、逐会话丢失 44.2% 替换边),但**其同序对照实验推翻了"顺序敏感"这一立项前提**,并衍生出"冻结建卡路径从未固定 temperature"的发现 → 已开 temperature 诊断实验。②③未做。
