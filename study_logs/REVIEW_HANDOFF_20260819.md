## 四、⚠️ 我自己认为最该被攻的地方(请优先审这七条)

**1. `dim1–dim5` 的数字来自衍生产物,不是逐臂原始行文件。**
`router_learned_triples_20260814.jsonl` 是 `train_router.py` 产的聚合物。
我全程按 ✅ 标注,但严格说应该是 ✅(一级衍生)。**若该文件本身有聚合错误,dim 那张表全错。**

**2. 分离手术的 usability 标注是纯代码从状态链机械生成的,与 gold 同源。**
这是**上界不是可部署形态**。真部署时标注质量受卡片抽取限制(卡片对源链精确匹配 70.0% ⚠️)。
**"教会优于接管 +11.24pp"这句话严格说只在 oracle 标注下成立。**

**3. 三个候选机制的卷内 null,可能是欠功效而非真 null。**
实验 B 的 43 槽位里 **23 个 set 占比恰为 0%**,变异被压缩在 0–30%。
我按判据判了"否定",但更准确的说法是"在该窄区间内无效应"。

**4. 我连续三次「先看到跨组相关、就地编机制解释、再做控制检验」。**
set / 日期覆盖 / 轮数,三次全是这个顺序,三次卷内全 null。
**这是方法论层面的系统性错误,不是三个孤立失误。**

**5. 头条 token「1.43×」无法复现,而我没能定位差异来源。**
我试了剔除 rt(1,990)、rt 按 wt 计(2,033),都到不了 2,720。
**这条要么档案口径未记录,要么数字本身有误 —— 但我没有证据说是后者。**

**6. 档案「提示词贡献 +5.64pp」的口径是我试出来的**(= "有 prompt 结果就用 prompt",
而非"只升级被路由派中的",两者差 2.2pp)。**这个定义此前不在任何文档里。**

**7. S5 是自建合成域。** 分离手术的全部结论(+18.42 / +11.24 / +6.46)只在 S5 上测过。
自然语料复核**冒烟即失败**:LME-TR 上编译臂 10.0%,55% 空证据。
按用户自定的放弃判据,**这些结论目前不可外推。**
