## 1. 一句话结论

22 篇深读中 same_problem = yes 为 0 篇、partial 为 22 篇:没有任何一篇同时具备 QVF/WikiState 的两个定义性特征——(a) 每条记忆的有效性按问题自身的参考时间或聚合形式逐题重推,使同一条被取代记忆对"现在"为错、对"2009 年"或 change_count 为对;(b) 多次转换的带日期状态链上的 change_count / count_before / longest_tenure / first_vs_last 问题,金标由链直接推导。但主张①的口号形式"全部竞品都是写入时盖章"已被证伪——EvoMem(SIGIR '26)、APEX-MEM(ACL 2026)、StateAuditor、StateMemWrapper、SodaMem(获胜配置为观察模式,0 取代边)均在读取时判定或不做写入裁决——必须改写为精确形式"全部竞品把有效性目标固定为'当前值',无一按问题参考时间重推每条记忆的有效性";主张②③未被移除,但各出现了必须引用的先例("Presentation, Not Mechanism" 的渲染匹配对照;MemTrace / A-TMA / StateAuditor 的读取侧归因与修复闭环)。威胁最高的一篇是 StateMemBench + StateMemWrapper(high,唯一一篇):其 App. F.1 提示词就是 QVF 的读者协议,且在 WikiState v2 上直接读原文与读 QVF 账本总体打平(81.25 vs 82.64,n=576,McNemar p=0.50)——QVF 的差异化只能建立在 change_count(62.5 vs 76.4)、每题输入 token(13,977 vs 2,553)与乱序稳健性上,不能建立在总准确率上。

威胁分布:high 1(StateMem)、medium 17、low 4(Supersede、Niksarli 双时态存储、TAC-KBP 2011 TSF、TAC-KBP 2013 TSF)。

### 3.1 [high] StateMemBench + StateMem + StateMemWrapper(arXiv 2608.19652 v1,2026-08-20)

**机制。** 三件产物。(i) 问题定义"state drift":相关事实已在上下文中,agent 仍按陈旧版本行动;在 LongMemEval-oracle(召回按构造为 1.0)上 DeepSeek-V4-Flash 的失败有 44.4%(16/36)属此类,跨家族确认(§3.2, Table 1)。(ii) StateMemBench:234 场景 / 322 探针,三域(科研、购物、个人理财);每场景是符号事件程序(规则声明、值更新、作用域例外、承诺、撤回),由确定性求值器回放出金标,"懒读者策略"族(最近、最频、未重算推导、过早失效)生成 drift 答案;封闭选项池 3–4 项把答案计为 current / superseded(drift)/ other(§4.3);Set A 190 场景 × 18 会话约 3k token,Set B 44 场景约 38 会话 7–15k token;文本由 sonnet-4.6 渲染,示例以 s15.t1 索引而非日历日期(D.2–D.4)。(iii) StateMem:TurnEncoder 每轮一次 LLM 调用产出状态单元 (id, content, priority, source, deps),标记"有被取代风险"的旧单元并给出替代;Update 阶段把单元状态置 superseded,被取代单元"对下一阶段隐藏"(§5.2);答题时按优先级渲染活跃单元 + 一次答题调用;日期仅"数据带会话日期时"作为可选戳(§5.1)。(iv) StateMemWrapper(§6.4, App. F):答题时单次提示词,第一节"State trace"(≤250 词)按时间顺序列出问题涉及实体的每次建立/更新/取代 [turn N] 并以当前生效值收尾,第二节四条优先规则(后者取代前者;常设规则压过一次性实例;推导值重算;仅显式取代或到期才退役);长度/成本匹配对照(同格式、泛化摘要、无链无规则)分离结构份额;不增加调用次数,但答题调用为全文规模(StateMemBench 中位输入 8.6k、LME 87k;F.5)。

**对新颖性的最强攻击。** 框架已被占:摘要把能力定义为长交互中事实/约束/决定被修订时答案"反映当前状态而非被取代状态",并用 LongMemEval-oracle 证明有效性失败不是检索失败,附裁判标注的失败分类(App. A)。机制是 QVF 的读取侧:Wrapper 逐题写出"问题触及的每个槽位的值链——初值、每次修订、当前值、时间顺序、轮号"并在作答前提交,这就是读取时按查询条件化的、轨迹优先的逐槽账本;QVF 的读者就是这段提示词(`scripts/repro_batch3.py:32` SMW_PROMPT = App. F.1)。它后端无关(F.3 两方法接口),六后端提升 +31.7 到 +66.6 且有更干净的匹配对照——"可包裹的有效性层"论证已被先做。在 QVF 自己的基准上,写入时卡片对总准确率无贡献(81.25 vs 82.64,p=0.50):审稿人会说 QVF = StateMemWrapper + 一个缓存。基准侧已有程序化金标、被取代值单独计分、反更新对照、长短两档、五种机械定义的失败模式;Table 2 会把 WikiState 归为"取代 ✓、drift 计分 ✗";WikiState 可被读成第四个域外加几种题型。它还证明状态优先记忆在 LME 上不损召回(0.656 vs 0.666),QVF 尚未过这一关。日期与"今天"锚在 StateMem §5.1/§5.3 已有,"带日期的卡"也不新。

**反驳。** (1) validity = f(memory × query) 可证缺席:StateMemBench 每个探针中被取代值都是计错项(§4.3;App. C "Drift scored");StateMem 把被取代单元"对下一阶段隐藏"(§5.2);Wrapper 规则 (1)"后者取代前者"与问题无关。322 探针、60 题扫描、LME/LoCoMo 运行中没有一题的正确答案是被取代值或链上统计量。WikiState 的 count_before / longest_tenure / first_vs_last(4 类中 3 类,576 题中 432 题)恰恰如此,且账本以问题日期为认证锚逐题重推——StateMem 要回答它们必须"反取代",其管线做不到。(2) 链按轮号索引而非日期:D.2–D.4 只有 s#.t#,日期是可选元数据,无时长与转换算术;WikiState 链来自带 start 限定符的真实 Wikidata 轨迹,"2009 年为真"与"哪段最长"可定义且机器金标。(3) 在 WikiState 上打平只在总分:同一 F.1 协议读原文在 change_count 上输 13.9 点(62.5 vs 76.4)——唯一需要合并后计数转换的题型——同时付出 5.5× 输入 token,乱序下掉 11.7 点(n=60,p=0.12,待全量)。该文没有测任何这些轴:成本对照是 155 token 指令差、答题调用全文规模,无乱序稳健性与逐构念定价。(4) 真实性与审计:StateMemBench 值"独立采样"合成、sonnet-4.6 渲染、3k–15k token、陷阱来自 StateMem 针对的同一策略族(H:"上界");WikiState 锚点对 542/542 链行逐字核验,33–38 个带日期会话/店约 14k token。(5) 纪律:单 run、小骨干、裁判与一个基底同家族(§6, H);WikiState 有配对 McNemar / CI / 多读者矩阵。(6) 截至 2026-09-02 项目未找到发布数据。净结论:该文占走读取时 trace-then-resolve 协议与"当前值 drift"基准构念;留下查询依赖的有效性函数、历史/聚合题型、带日期真实链、成本/乱序/归因轴——QVF 必须在这些轴上论证,不能在准确率上。

### 3.2 [medium] A-TMA(arXiv 2607.01935 v2,2026-07-08,NUS)

**机制。** 宿主记忆系统上的三层覆盖。银行层(写入时,§4.3):记录 r_i = (内容, 时间/来源位置, 状态 ∈ {active, superseded, transition, unknown}, 类型化链接 {supersedes, superseded by, evolves from/to, scoped exception, coexistence}, 宿主元数据);新记录到达时 Sentry(SentenceTransformer + topic/logic 头,训练)提候选,Judge(Qwen2.5-3B-Instruct,QLoRA SFT + 奖励优化,A.8)返回冲突状态/类型/融合动作/链接,提交时置 s_i←superseded、s_j←active 并加互链(Eq. 8);作者称其为第三选项:"保留两状态、改状态、类型化关联"。检索层(读取时,§4.4):"轻量规则式查询画像器,非分类器非 LLM",按时间/变化提示词计数给 v_q ∈ {current, historical, transition, neutral},宿主种子按视图做关系跳与语义跳,稳定预排;可选有界控制器只能重排。QA 层(§4.5):标签 λ ∈ {cur, hist, tran, link, raw} 是"早先层已产出的迹字段的确定性投影"——superseded/archived/stale/inactive 行变 historical,active 行变 current;序列化"保持检索选出的内容顺序",提示规则"除非问题明确问过去,当前记忆视为活跃状态"。答题 qwen2.5:3b,top-k=5;离线裁判 llama3.3:70b。基准 LTP:10 段 LoCoMo 对话 × 40 可变槽位,每槽为"两线索状态单元"(旧线索在 0.12–0.42 时间分位,当前/冲突线索在 0.58–0.88);更新类型按类别:temporal(职位/居住)、显式否定、值差异、作用域不匹配;每单元两探针(fact recall = 旧状态;conflict aware = 当前状态)= 800 探针;金标由构建器写、两位标注员在 80 单元分层样本上核验(A.4)。

**机制。** 基准 + 数据生成器,无方法。(1) 每个模拟用户一个"心智状态图" G,含人物、社交关系、生活事件与类型化偏好属性;偏好由"类型化依赖边"连接,"每次变化记录触发事件作为溯源"(§3)。图"不提供给被测模型"(§3)。(2) 生成:事件按状态与历史条件采样(§4.1);以 p_evo=0.15 一个生活事件改变 2–5 个偏好并级联更新,并生成一段"不陈述新偏好值"的短事件提及对话(§4.2);关键:"演化不刷新偏好的表达时间戳"(§4.2),所以旧值仍是最后明说的值。每偏好表达时间戳 τ(p_i);30 天陈旧阈值后偏好可用于"时间回忆"(§4.4)。表达变体(显式/隐式)只重写表达偏好的轮次(§4.3)。(3) 任务:嵌入完整 6 个月史的 5 选 MCQ,"识别最符合用户当前偏好的助手回复"(§5)。每项四个备选含"以原值 v_old 的前演化干扰注入"(§5.1);5-LLM 共识过滤(GPT-4.1、Gemini-3-flash、o4-mini、Claude-haiku-4.5、Claude-opus-4.6)只保留五者无史时全答错的项(§5.1)。(4) 发布工件(HF 卡):`benchmark` 4,245 行含 `has_evolved`、`distractor_letter`、`preference_evolution`("含触发事件的演化史");`mental_state_graphs` 360 行含 `preference_record` = "按日期键的偏好状态快照"与 `timeline_metadata` 含"偏好变化计数"。Fig. 2 示例一个槽(emotional_tone)变两次(10 月、11 月),response_structure narrative_storytelling → step_by_step_action_plan。基准隐含的有效性语义全局且在生成时固定:前演化值总是错选项("前演化值为有效的困难负例干扰",§4.2);任何处无写入/读取时讨论(write-time / read-time / ledger / Wikidata / point-in-time 0 命中)。

**对新颖性的最强攻击。** 假设同一问题。HorizonBench(Meta/UW/Stanford/OpenAI,2026 年 4 月)已建了 WikiState 使用的精确基准配方——带每槽日期与溯源标记变化史的结构化真值状态图,渲染为带日期第一人称会话,被取代值植入为困难负例——但规模约 30 倍(360 用户、45,006 候选过滤到 4,245 项、每项约 163K token、30 域),5-LLM 史必要性过滤,三个受控维度,25 个前沿模型,bootstrap CI 与约 900 人工标注项。它公开发布 `mental_state_graphs` 含"按日期键的偏好状态快照"与逐用户"偏好变化计数",所以 change_count / first_vs_last / point-in-time 题一下午就能在其上模板化;审稿人可说 WikiState 是已发布资源的 144 链 Wikidata 换皮加四个题模板。QVF 的动机发现——模型返回原始陈述值而非更新状态——已以更强统计发表(25 模型全部、最佳模型 >35% 错答、0–14 天短期仍存,§6.2–6.3),论文已论证"检索增强方法面临同样局限"并呼吁"随生活事件更新的显式偏好状态表示"(§7),即状态卡。其检索 vs 信念更新分解与 QVF 账本误差归因是同一诊断动作。它还把自己置于 PersonaMem-v2 动态偏好与 LongMemEval knowledge-update 之间,显示取代基准空间已拥挤。

**反驳。** (1) 有效性类型。HorizonBench 只测 WikiState 三类有效性中的一类(当前值),结构上不能测另两类:每个演化项前演化值都是干扰(§4.2, §5.1),所以在写入时硬删或"退役"旧值的系统(Mem0 DELETE、MemStrata)可拿满分,基准永远无法察觉该系统对"2009 年为真""雇主变了几次""哪个职位最长"是错的。WikiState 的 count_before / longest_tenure / first_vs_last / point-in-time 让旧值成为答案;这就是 "validity = f(memory × query)" 的操作内容,HorizonBench 含零道此类题(全文 grep)。(2) 无方法、无记忆系统证据。论文不提方法,只评全史提示(§6);无 Mem0/Zep/RAG 数字,写入 vs 读取时裁决从未讨论。其 §7 方向——"随生活事件更新"的状态表示——是写入时更新模型,与 QVF 写入不裁决卡 + 逐题读取账本相反。(3) 金标出处。WikiState 金标纯由 Wikidata P39/P108/P54/P551 链推,值客观、有 start 日期;HorizonBench 金标是 LLM 生成的主观属性,人类多数准确率 56–64%、κ 0.37–0.51、19% 项三位标注者全漏(§5.3, App. D)——对需要无歧义链值的计数/聚合题不可用。(4) 被测能力。HorizonBench 的演化是未陈述的推断("不陈述新偏好值",§4.2):模型必须猜火灾改变了用户语气。WikiState 测显式陈述的带日期取代及其聚合——不同技能,也是账本可证明之处。(5) 格式与链规模。HorizonBench 项暴露一次演化与一个 v_old 的 5 选识别;WikiState 每槽多次带日期转换且要产出计数/值。净:HorizonBench 占走"取代后当前状态、基准配方"句;留下查询条件化有效性主张、历史/聚合题型、写入/读取方法轴。Jeremy 须在基准对比表中引它(当前值 = 是、point-in-time = 否、聚合 = 否、方法 = 无),不能对"锚定原始值"发现主张优先权。

**未核实。** 是否有基准项针对演化 2+ 次的偏好(Fig. 2 显示 emotional_tone 在图中变两次,HF 字段 `preference_evolution` 承诺"演化史",但论文未报每目标槽变化分布);逐用户偏好变化计数(HF `timeline_metadata` 存在,值未检);候选注"被 MemTrace 引用"未核;仅见 v1;abs 页与论文无出处;README/HF 卡仍是占位 "arXiv:XXXX.XXXXX";发布 `mental_state_graphs` 是否含每槽显式带日期转换记录(卡片说"按日期键快照";未下载);人工标注项数仅近似(约 400 与 516)。

### 3.16 [medium] DynamicMem(arXiv 2606.22877 v1,2026-06-22,明尼苏达大学等;CC BY 4.0)

**机制。** 仅基准。代码 github.com/wenyaxie023/DynamicMem,数据 huggingface.co/datasets/xiewenya/dynamicmem。构造(§3):PersonaHub 的 10 个人物;每用户 15 个月(2023 Q4–2024 Q4)分 5 个季度检查点;画像分为 Attributes / Habits / Preferences(§3.1)。金标状态经类型化 delta 演化:"属性 Add/Remove/Modify"、"习惯 Acquire/Adjust/Drop"、"偏好 Shift/Refine";每 delta "必须带指回世界背景的显式因果理由"(季节、生活事件;Figure 2 例 Modify:"workplace: hybrid → field")。Table 1:883 属性 + 466 习惯 + 488 偏好实例 = 1,837 项,383 类型化 delta(约 21% 项曾变化),17,715 条 app 日志事件跨 16 app / 66 API,每用户约 2.2M token、1,772 事件。证据不是对话:原始 app 日志(时间戳、app、API、请求参数、响应)由有状态 app 环境生成,使"每条记录动作反映用户当时的画像"(§3.3)。评测(§4):"每检查点系统只能访问该季度末之前的 app 日志"(§4.1);两任务族——State Completion(1,824 题:在固定 JSON schema 中填当前画像空白字段)与 Personalized Service(1,810 题:场景只给时间/地点,如"周日 10:15 → 为用户周末购物起草提醒");3,634 题 / 4,994 计分点;分数 s = 0.8·Core + 0.2·(Detail/2)。Retention vs Update 分析(Figure 8):retention = "重问自 C1 以来一直为真的事实";update = "金标值刚从最近前值变化的事实"。错误分类(§5.2):Irrelevant Evidence / Identity Miss / Detail Miss / Conflated Evidence("填同一角色的竞争替代也被浮现")/ All Clear。

**证据指针。** 系统:Oracle 上界、Vanilla RAG、HippoRAG2、A-Mem、MemoryOS、SimpleMem;答题 gpt-5-mini,检索器 text-embedding-3-large(§5)。发现 1(§5.1, Figure 5):State Completion 从 C1→C5 对每个系统下降——RAG −4.4、HippoRAG2 −6.6、A-Mem −8.9、MemoryOS −14.2、SimpleMem −16.7 点——而 Personalized Service 持平或上升(RAG +2.8、HippoRAG2 +4.0、A-Mem +4.9、MemoryOS +1.2、SimpleMem −1.5);金标证据召回在 State Completion 上"降 20 到 24 点"。发现 2:偏好退化最多(C1→C5 约 11–26 点),习惯持平,属性早降后平。发现 3(Figure 8):"无单一架构在 retention 与 update 上都赢";HippoRAG2 在变化偏好上"C2–C5 变化检查点平均 68%,对比其他非 Oracle 系统 56–59%";update 随语料增长"A-Mem(89% → 39%)与 SimpleMem(89% → 47%)急降";MemoryOS 在习惯保持上丢约 11 点而 A-Mem 终点高于 C2 5.7。发现 4 / Table 2:同一记忆下习惯从 State Completion 到 Personalized Service 降 43–50 点(模型侧瓶颈)。错误分析(§5.2, Figure 9):结构化系统集中在 35–36% Identity Miss 与 28–33% Detail Miss;RAG 36% Detail Miss / 31% Identity Miss;MemoryOS Irrelevant Evidence 29% SC vs 其他 23–24%;">93% 失败可追溯到记忆系统检回什么而非答题模型"。自述局限(§6):合成,"不为宣称全维度行为真实性"。结论呼吁"把 retention 与 update 当作不同目标并可靠追踪画像如何、为何变化"的架构。

**对新颖性的最强攻击。** 假设 DynamicMem 是同一问题。那么 WikiState 是 DynamicMem 已在更大规模做的事情的小型、显式陈述、对话渲染特例:DynamicMem 金标是演化用户槽上的类型化转换图(带因果归因的 Add/Remove/Modify,1,837 项上 383 次转换),在 15 个月、2.2M token 上于五个带日期检查点评测,而 WikiState 是四个 Wikidata 属性上 144 条链、42K/104K token;其证据更难(隐式、散布 16 个 app)而非点名槽位的第一人称陈述。其 retention vs update 分解(Figure 8)已用逐系统数字展示 QVF 的动机主张——"没有系统能既保住不变事实又替换变化事实"(HippoRAG2 68% vs 56–59%;A-Mem 89%→39%),其 Conflated Evidence 错误类已点名 QVF 账本要修的失败(当前与被取代值共同浮现)。它还把 >93% 失败归于检索,所以审稿人可说社区已知瓶颈在记忆侧且已有检查点日期状态金标的基准;QVF 读取时账本是对 DynamicMem Conflated Evidence 的增量修补,WikiState 用更少用户、更少 token、更易证据复制了 DynamicMem 设计。

**反驳。** DynamicMem 可证不能测 QVF 针对的失败。每个探针都是"检查点时的当前值",记忆截断在该检查点(§4.1),其 update 金标按定义是最新值。每次变化都硬覆盖或删除旧值的系统(Mem0 式写入时裁决、MemoryBank 式衰减)在 DynamicMem 上毫无损失——反被奖励——而在 WikiState 上直接输掉 count_before、longest_tenure、first_vs_last。所以 DynamicMem 的 "retention vs update" 是新近 vs 遗忘曲线,不是查询条件化有效性:其中没有任何题以被取代值为正确答案。其次,转换放在季度长窗口里,无陈述日期无逐字 span,所以 QVF 评测的账本操作(认证带日期卡、按日期编译、计数转换、合并相邻等值)无金标可判;WikiState 链带 start 限定符与渲染的带日期陈述,正是为使这些操作可判定。第三,逐槽链浅(1,837 项上 383 delta),对一个槽多次取代的历史聚合——WikiState 的核心——结构性缺席。第四,是 app 事件证据非对话记忆,不提记忆机制,所以 QVF 的写入时状态卡与读取时账本在那里既无对应也无竞争者。最后,按本地红队笔记,其 93% 检索侧归因在未控制读取侧协议下得出;QVF 的全覆盖测量显示仅读取协议就大幅移动准确率,这使 DynamicMem 成为方法学对照而非先有答案。净:引为最近的检查点状态基准与保留/替换困境的独立证据;查询条件化有效性论点与历史聚合题型仍未被占。

**未核实。** Conflated Evidence 百分比:Figure 9 两次抽取给出 0–5% 与约 8–12%;逐系统绝对 C1/C5 分数(正文只给 C1→C5 差);update 探针是否在后续检查点重问还是仅"变化检查点";"stale / supersede / point-in-time / temporal validity" 在全文的精确缺席(抽取仅报 §1 与 Related Work);是否引 STALE、MemConflict、ChronoScope;2+ 次转换的项数;1,772 事件/用户 × 10 = 17,720 vs Table 1 的 17,715(假定舍入);非牵头单位取自 HTML 头抽取。

### 3.17 [medium] TimelineQA(Findings of ACL 2023,arXiv 2306.01069 v1;Meta / Cornell;代码与模板 github.com/facebookresearch/TimelineQA)

**机制。** 合成生活日志生成器 + 模板 QA,无方法。(1) 人物:出生日期(生成时 18–75)、性别、姓名、出生城市、教育,然后概率生活事件链——src/persona_generator.py 抽 num_marriages ∈ {0..4} 带结婚/离婚年龄,num_jobs ∈ {0..4} 带 started_job/quit_job 年龄与每份工作的职业列表(§4)。(2) 情节:从 18 岁到末年按时间尺度生成——终身(出生、大学/研究生迁移与毕业、工作迁移、婚姻)、年度(旅行、体检)、月度(宠物护理)、周度(烘焙/做饭、约会、爱好、杂货)、日度(用餐、聊天、运动、阅读、电视、社交媒体)(Table 1, Table 9:25 种事件)。每情节有逻辑表示(日期、地点、人物、属性)与从几个固定模板(data/templates.json)选一渲染的文本;"通过约束保持一致"强制互斥(如旅行时无牙科检查)。密度 sparse/medium/dense 与时长为生成参数。(3) 题:原子 what/where/when/who 题在情节创建时产出,答案为该情节的 span;复杂题由逻辑 DB 上 42 个 SQL 支持的模板实例化(multihopQA/queryfile.csv)——count("我在 {month} {year} {exercise} 了几次?")、argmax("我在 {month} {year} 跟谁聊得最多?""我上次跟 Chloe 买杂货是什么时候?")、average、list——金标通过在情节表上跑 SQL 计算(§4, §4.1.1)。每道多跳题附真值证据集(平均 1,170 情节,约 20% 在 1,024 token 截断;Table 3)。(4) 基线只是读取时管线:原子——DPR top-5 检索进 RAG-Token vs RoBERTa-SQuAD 抽取读者,检索器 zero-shot / 微调 / oracle(§5.2);多跳——检索器(oracle / 微调 SBERT / 模式规则)→ NER + 模式把情节转为固定逐主题表 → Tapex 或 BART TableQA 读者(§5.3);InstructGPT-175B 在 100 道抽样题上(App. C)。情节是生活日志行("2010/01/09, I had lunch. I ate sushi."),不是与助手的聊天会话,且未评任何带写入路径的记忆系统。

**证据指针。** 数据:3,000 份日志(sparse/medium/dense 各 1,000),128,023,476 条目,每条 8.4 token(Table 2);25 事件类型(Table 9)。原子 QA 测试:120 份保留日志每份 5,000 题(60 万)。多跳:train 240 日志 / 8,586 题,valid 120 / 4,302,test 120 / 4,284;每日志约 35 查询;每题平均 1,170 证据记录,约 20% 截断(Table 3)。原子结果(EM/F1,Table 4):Extractive FT 82.6/93.8,OR 83.3/94.8,ZS 24.1/47.3;RAG FT 40.3/57.5,OR 73.7/84.4,ZS 8.4/32.9。多跳指称准确率(Table 5):Tapex-large 微调 59.0(oracle 检索)/ 32.7(FT 检索)/ 33.0(ZS 检索);zero-shot Tapex-large 6.5;BART-large FT 47.0 oracle。分解(Table 6,Tapex-large FT oracle):count 75.9%、list 62.7%、argmax 47.2%、average 11.1%;按证据量 85.1%(≤10)、52.5%(10–100]、19.2%(100–1000]、4.3%(>1000)。InstructGPT-175B 100 题(Table 10,人工评):33.0 oracle / 25.0 FT / 18.0 ZS。算力:25.4 A100 GPU 小时(App. B)。无 token/美元。

**对新颖性的最强攻击。** 假设 TimelineQA 是同一问题。那么 WikiState 是限制到四个 Wikidata 属性、换皮为聊天会话的 TimelineQA:TimelineQA 已 (a) 建了就业与婚姻状态一生变 0–4 次的人物(persona_generator.py),(b) 把这些变化渲染为带日期第一人称句("I moved to {location} for a new job on {date}"),(c) 每个金标纯由底层逻辑链经 SQL 推出,恰是 WikiState 的"金标纯由链推导",(d) 定义了婚姻与迁移上的 count / first / most-recent 题模板(q33–q37),与 change_count 和 first_vs_last 一一对应,以及对求和时长的 argmax 模板("我跟谁聊得最多",q4),结构上是 longest_tenure,(e) 把它们混进数万条带日期干扰条目(聊天、用餐、电视)的干草堆,每题约 1k 证据记录,并显示检索质量与证据集大小而非阅读是瓶颈(Table 5:59.0% oracle vs 33.0% 微调检索;Table 6:≤10 证据 85.1% 到 >1000 证据 4.3%),这与 QVF 账本要修的诊断相同,(f) 已论证读取时"选对证据集,再编译成表并聚合"管线——检索后经 schema 归一化的表上跑 Tapex——功能上是逐题编译的带日期账本。据此 QVF 的账本是带 LLM 的 TableQA,WikiState 是更小、Wikidata 来源、把时间窗题改名为"有效性类型"的 TimelineQA;这篇 2023 年 Meta 论文带公开生成器,会是审稿人用来否定基准设计与"先编译再作答"两个主张的先有技术。

**反驳。** 该论证在 TimelineQA 可证不含之物上失败。首先,WikiState 追踪其历史的槽在 TimelineQA 中从不以可观察值存在:雇主/职业在人物中抽取但没有模板渲染它(templates.json job_move 只有 location/date/people;grep company/employer/profession 只见 "with_company" 人物标志),且从不生成 quit-job 与 divorce 情节——所以不能从日志提问或回答雇主是什么、曾是什么或有几个。其次,唯一链形模板(q33–q38)被数据构造代码显式跳过,在 4,284 道评测题中缺席;评测的类型是对重复日常事件(用餐、聊天、运动)的计数/argmax/平均,不是状态转换。第三,TimelineQA 根本没有有效性轴:没有条目对任何题是错的,没有旧记忆误导的当前值题,没有 point-in-time 状态题,没有"哪个值最长",一致性约束阻止了 WikiState 干扰会话与 QVF 认证步所针对的复述与冲突。第四,它不是记忆系统场景:无写入路径、无助手对话、无卡、无逐会话溯源;其"编译成表"是对已知 schema 的固定 NER/正则管线,作者自称只有"利用生成管线"才"近乎完美"(§5.3),不是 LLM 构建、查询选择、带转换计数的日期账本。QVF/WikiState 做而 TimelineQA 可证不做的:把有效性定义为一个槽上三类的 f(memory × query),提出同一证据下答案不同的当前 / point-in-time / 历史聚合题,并在渲染为多会话对话的真实 Wikidata 链上评写入时卡 + 读取时账本编译。正确定位:引 TimelineQA 为最早的人物生活日志聚合 QA 祖先(SQL 金标的 count/first/last),并说明 WikiState 加了它缺的取代轴。

**未核实。** 发布的 4,284 题测试集含零道婚姻/迁移题系由 create_qa_data.py 跳过 '?' 行、论文沉默与 Table 6 类型总数推断,未下载生成的 queries.csv 确认;Findings of ACL 2023 出处由 Anthology 页 2023.findings-acl.6 标题确认;是否有后续 arXiv 版本或数据集修订(HTML 仅 v1);InstructGPT 基线是否有 zero-shot 以外的提示设计;每日志实际实例化的复杂模板数(论文说 42 模板、约 35 查询/日志)。

### 3.18 [medium] Temporally Anchored Relation Extraction(Garrido, Peñas, Cabaleiro, Rodrigo;ACL 2012,P12-1012)

**机制。** 管线(Fig. 1):对查询实体 IR 检索候选文档 → 基于图的文档表示(依存 + 共指 + 语义 + 时间边,§3)→ 从 Wikipedia infobox KB 远监督训练的逐关系线性 SVM 抽取器(§4;Mintz 式;对产出同一值的文档求 margin 和)→ 时间锚定(§5)。时间表示(§2):TAC-KBP 2011 "不精确锚区间",有序 4 元组 (t1,t2,t3,t4) 表示关系始于 [t1,t2] 某处、止于 [t3,t4] 某处;任何端点可无约束。锚定为四步(§5):(1) 用 TARSQI 链接加 [Event-preposition-Time] 模式表示文档内时间信号,归一为 within / throughout / beginning / ending / after / before;(2) 每文档选证据:默认在 'within' 链接假设下取文档创建时间(DCT),否则取(BFS)离实体-值依存路径最近的时间表达;(3) 链接类型映射为约束(Table 2:Before → t4=first;After → t1=last;Within/Throughout → t2=first,t3=last;Beginning → t1=first,t2=last;Ending → t3=first,t4=last;DCT d → t2=d,t3=d);(4) 对同一(关系, 值)跨文档聚合:"最大化 t1 与 t3、最小化 t2 与 t4,以收窄边界"。输出:(实体, 槽, 值)三元组集合,各带一个固定 4 元组。无 LLM、无读者、无问答。

**证据指针。** TAC-KBP 2011 Temporal Slot Filling(Ji et al. 2011):KB "由 Wikipedia infobox 编译",100 实体 898 三元组,每实体至多 8 槽(per:cities/stateorprovinces/countries_of_residence、per:employee_of、per:member_of、per:title、per:spouse、org:top_members/employees;§6, fn 3),从 170 万文档集抽取;槽"为列表值……可能在不同时间点"(§6.1)。指标(§6.2):若值正确,Q(S) = 1/4 · Σ_i 1/(1+d_i),d_i = |k_i − r_i| 以年计,四端点;P = Q/M,R = Q/N。Table 3(微平均,第 9 行):关系抽取 Setting 2 P 0.45 / R 0.08 / F 0.14;时间锚定 Setting 2-I(仅 DCT)P 0.31 / R 0.06 / F 0.10 = RE 上界的 69%;Setting 2-II(文内时间表达,DCT 回退)P 0.27 / R 0.05 / F 0.09 = 60%。per:employee_of 在每个设定中为 0(第 2 行)。Table 4(官方运行,712 三元组答案键):Setting 2-1 P 0.2996 / R 0.0703 / F 0.1139——五参赛者中精确率最高,F1 第三,落后 BLENDER(F 0.2250)。头条发现(§6.2, §8):仅 DCT 基线"难以被"分析文内时间表达击败;学习链接→区间映射被称为"困难的开放研究问题"。

**对新颖性的最强攻击。** Garrido et al. 2012 执行 TAC-KBP 2011 Temporal Slot Filling 任务,已 (a) 把雇主、职位、成员、居住框定为"有效性天然锚定于某个时间段"的 fluent(摘要)——恰是 WikiState 的槽族;(b) 从 Wikipedia infobox 建金标,每三元组带时间锚,槽为列表值"可能在不同时间点"(§6, §6.1)——即带日期值的逐槽状态链,与 WikiState 从 Wikidata start 限定符的构造相同;(c) 逐文档抽取带日期的时间证据项(文档日期或文内表达)及其对事实的类型化链接,映射为约束,并对所有支持文档收窄区间聚合(§5, Table 2)——结构上与 QVF 逐会话状态卡编译为带日期账本是同一两阶段设计,且有效性对象(起止范围 4 元组)比 QVF 仅起始日期的账本更丰富;(d) 明确指出时间锚定抽取"需要跨多文档聚合证据"(§7)。据此 QVF 的卡→账本是 2012 年日期聚合用 LLM 重做,WikiState 是 TAC-KBP TSF 换成第一人称聊天;"多文档/多会话"新颖性与"槽值仅在区间内有效"问题陈述都是先有技术,槽清单也不新。

**反驳。** (1) 没有任何问题进入 Garrido 系统:输入是"查询实体"+ 关系(Fig. 1),输出按端点到答案键的距离计分(§6.2)。有效性是每三元组的固定属性;没有"一条记忆对'2009 年为真'对、对'现在是什么'错"的概念。QVF 的定义性主张——validity = f(memory × query),逐题重推——没有对应。(2) Garrido 只在同一(关系, 值)内聚合(§5 措辞);从不跨一个槽的多个值推理,所以不能排序值、计数转换、找最长任期或让后值取代前值。QVF 账本建在一个槽的全部卡上,编译步合并相邻等值并计数转换;WikiState 四类题全在这个跨值层面,TSF 中缺席。(3) 锚定在抽取时由确定性收窄规则一次决定(写入时);QVF 按设计在写入时不裁决,推迟到读取时。(4) 数据机制实质不同:第三人称新闻语料 vs 带设计干扰会话与 owner 归属的带日期第一人称会话;TSF 金标是逐值端点,WikiState 金标是聚合题的链推值。(5) 论文未在实证上建立历史推理:锚定 F 0.10(F 0.14 上限的 69%)、per:employee_of = 0,作者自己的结论是文内时间表达难以利用、DCT 是最强信号——与 QVF 认证来源 span 中陈述日期相反。(6) 无读者协议或轨迹渲染。Jeremy 保留的:引 TSF 谱系为 fluent 槽问题与卡式带日期证据的抽取侧祖先;放弃发明 fluent 槽框架或槽清单的主张;三条不可让渡主张完整。

**未核实。** 候选短语"逐句时间证据"不准确:证据按文档(DCT)或离实体-值路径最近的单一时间表达;TAC-KBP 2011 TSF 指南在 §2/§6 报告之外的细节(如答案键是否允许一个槽两个值区间重叠)未对 Ji et al. 2011 核对;代码或系统输出可得性未说明;配套 TAC 2011 系统论文(Garrido et al. 2011)未读;后来的 TAC-KBP 2013 TSF(本次已读,见表第 22 行:未加跨值排序)与 Talukdar et al. 2012(WSDM,CoTS)是否加跨值排序——后者未读。
