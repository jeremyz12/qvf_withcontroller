# QVF 实验日志（STALE 弱读者主线）

协议：STALE（HF `STALEproj/STALE`，CC BY 4.0）前 35 条目 × 3 维查询 = 105 查询；
读者 qwen3:4b（本地 Ollama，temperature 0）；抽取/判分 claude-opus-5；
top-k=10；judge 规则 = 须反映新状态且不得把旧状态当作当前。

## ✅ Held-out 主结果（论文主数字）

冻结 v4 在从未接触的条目 35-104（70 条目 × 3 维 = 210 查询）上一次性运行：

| | 总体 | dim1 | dim2 陷阱前提 | dim3 隐式 |
|---|---|---|---|---|
| direct | 26.2% | 38.6% | **0.0%** | 40.0% |
| **qvf_v4（冻结）** | **52.4%** | 77.1% | **30.0%** | 50.0% |

- **系统绝对性能与开发集完全一致（52.4% = 52.4%）——无开发集过拟合迹象**
- 提升 +26.2pp（2.0 倍）；配对分析：qvf 独对 63 例 vs direct 独对 8 例，
  McNemar 式双侧 p ≈ 1e-11
- direct 在 70 个条目的陷阱前提维度上一题未对（0/70）；v4 将其提升到 30%
- 引擎健康：561 接收 / 14 拒收（2.4%）、210 查询仅 1 次回退
- held-out 运行成本 ≈ $20

**可写进论文的一句话**：在 held-out STALE 上，免训练的 QVF 神经符号管线把
4B 弱读者的正确率翻倍（26.2%→52.4%，p≈1e-11），陷阱前提维度从 0% 提到 30%，
无微调、全程可审计、单查询抽取成本约 $0.09。

## 每步的归因证据（为什么这么改）

1. **v1 无增益 → 三路归因**：检索缺失 47.6%（该子集 direct=0%）、读者不服从 28.6%
   （引擎正确 block 后仍答错）、抽取仅 6.7%（拒收率 2.7%——抽取喂得饱 fail-closed 契约）。
2. **v1.5 手术部分验证**：手术做对时 53.6%（vs 标注式 31.5%），但暴露读者被
   "没信息就拒答"规则带偏（dim3 窄上下文），及 13 例"只留旧"（抽取漏建竞争）。
3. **v2 机制成立仪器失败**：补检索一旦捞回新状态 0%→42.9%，但更新词 BM25 只救回
   7/47（通用更新词在 300 轮草垛中被淹没）。
4. **v3 的免费预检**：检索微基准（零 LLM 成本）证明稠密检索新状态命中率
   51.4%→80.0%（首遍）→96.2%（含补检索），随后端到端兑现 17.1%→42.9%；
   dim2（陷阱前提）2.9%→40.0%（14 倍）。
5. **v4 靶点**：v3 最大损失桶 = 未解决冲突 24 例仅 12.5%——抽取无显式更新语言时
   引擎按规范拒绝 recency（正确！），但读取策略随之丢弃证据（错误）。修法 =
   校准 recency：仅在符号层确认同槽位冲突后，保留冲突双方 + 按时间加保留意见作答。

## 与相关工作的差异化（实证后的表述）

- vs MemChain（训练压缩策略）：零训练；被取代记忆标注保留而非丢弃；全程可审计
  （每个判定带 span 引用与规则依据）；组件可独立替换（本日志即证明：检索器、
  读取策略、读者三次独立升级，其余组件不动）。
- vs MemStrata（写入时确定性取代）：读取时按查询裁决；其"嵌入区分不了矛盾与复述
  （AUROC 0.59）"结论支持我们用 LLM 抽取而非嵌入做语义判定；我们的 v4 冲突策略
  展示了确定性规则欠定时的校准降级路径。
- 弱读者定位的实证依据：强读者（opus）任何中间表示均无增益（LongMemEval-S 82 题
  三条件并列，见 results/planA_s_15pt.jsonl）；qwen3:4b 上 direct 仅 17.1%，
  处理效应空间大。
