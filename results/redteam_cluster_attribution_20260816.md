## 0. 判决(先判决,后数字)

**两个旗舰显著性数字在聚类稳健口径下依然成立。**

- 旗舰①(WikiState-v3 扩充卷最强配对,P108-ext,台账"109胜3负 p=9e-29"):题级朴素 p=9.0e-29 → 实体簇级(69 簇)聚类稳健 p=3.6e-18。数量级从 e-29 收缩到 e-18,但仍远超任何常规显著性阈值(α=0.001)十几个数量级,判决不变。

聚类校正让 p 值收缩 8~14 个数量级(因为把有效样本量从题数砍到约 1/4 的实体数),这正是"~79 实体 × 4 题"结构本该带来的稳健性折扣;两个旗舰在收缩后仍处于 1e-14~1e-18 量级,统计结论没有被推翻。9 个非 WikiState 家族的已有对照组里,3 个边际显著对照(heldout2 两行、STALE dense_recency)簇级 p 与题级 p 同向变化不大(簇数≈题数或簇内高度一致);2 个 LoCoMo 对照簇数极小(4-5 簇),簇级检验功效不足,不应再用作显著性主张的依据(仅 5 观测单位无法支撑传统意义上的"显著/不显著"判断,这本身就是聚类校正要揭示的问题)。

## 1. 聚类稳健显著性(WikiState 家族 + 已有对照组全量)

### 1.1 方法

`scripts/bootstrap_ci.py` 原有逻辑:单文件内 `mode` 字段区分 test/base 臂,按 `cluster_of(question_id, kind)` 分簇,簇重采样 bootstrap 出 95% CI,外加题级精确符号检验 p 值(**这就是"朴素 p"**——把每题当独立试验,忽略同一实体 4 题相关)。

本次扩展:
1. **新增簇级符号检验**("聚类稳健 p")——每个簇按其内部 mean(test)−mean(base) 的符号投一票(赢/输/平),再对簇级赢/输计数跑同一个精确符号检验公式。这是朴素 p 的直接稳健版本:单位从"题"换成"簇",检验公式不变,可与朴素 p 并排对比。
2. **新增跨文件配对**(`TWO_FILE_COMPARISONS`)——WikiState 家族的 test/base 臂分别落在两个独立文件里(不是同一文件内 `mode` 切分),按 `question_id` 交集配对后走相同的分簇/检验流程。
3. **WikiState 簇定义**(`cluster_of(..., kind="wikistate")`):S5 复杂查询文件自带 `uid` 字段直接取用;`wiki_*`/`newdom_*` 系列文件没有 `uid` 字段,簇 id 从 `question_id` 按 `"_dim"` 切分还原实体 id(如 `wikiP108000-Q47391136_dim1_current_query` → `wikiP108000-Q47391136`),与 STALE 家族既有的 `cluster_of` 切分规则同构。
4. 聚类 bootstrap 95% CI(簇重采样,10000 次,seed=20260803)不变,新增列 = 有效簇数。

## 2. Oracle 上界归因表(100% − 策略 = 路由损失 + 臂能力上限)

### 2.1 方法

`scripts/redteam_oracle_decomp.py` 只读 `results/router_learned_triples_20260814.jsonl`(`scripts/train_router.py` 产物,5511 题 × 4 臂三元组,含交叉拟合 p̂ 与实测 token),零 LLM 调用,独立重算:

- **oracle 准确率** = 每题只要有任一臂答对就记为对(逐题事后诸葛亮上限,与策略无关,只由这 4 个臂本身的能力决定)。
- **手写路由** = 归档 `v42_correct` 字段(v4.2 生产路由的实际结果)。
- **学习路由(每个 λ)** = 独立复算 `argmax_a[phat_cv[a] − λ·(tok_a/T_ref)]`,逐题在可用臂集合上取分最高的臂,用其 `correct` 结果统计准确率;`T_ref` 用全部臂行 token 均值重新算出(7444.7),与 `router_learned_report_20260814.md` §1 记录的 7445 核对一致(四舍五入误差内)。

分解式:`100% − 策略准确率 = (100% − oracle) + (oracle − 策略准确率)`,右边第一项**臂能力上限**(4 臂能力天花板决定,与路由策略无关,固定值)、第二项**路由损失**(该策略相对完美路由丢的分)。

**独立验证**:本脚本重算出的 17 档 λ 学习路由准确率(73.18/73.14/73.16/73.09/73.14/72.96/72.80/72.53/72.44/72.46/72.27/72.20/72.09/71.86/71.53/70.30/69.19,对应 λ=0.0~2.0)与 `router_learned_report_20260814.md` §3 Pareto 前沿表逐档比对**完全一致**(oracle 82.14%、手写 70.15% 亦一致),证明本次独立重算未引入新误差。

### 2.3 读法

- 手写路由的 29.85pp 总缺口里,**60%(17.86pp)是臂能力上限锁死的,只有 40%(11.99pp)是路由策略本身可挽回的路由损失**——换句话说,就算把手写路由换成完美路由,准确率上限也就是 82.14%,而不是 100%。
- 学习路由(λ=0,纯准)把路由损失从 11.99pp 压到 8.96pp,收回了约 25%(3.03pp)的可挽回损失,对应准确率 70.15%→73.18%。
- λ 越大(越省成本),路由损失越接近手写路由的水平(λ=1.5 时路由损失 11.85pp,几乎与手写的 11.99pp 打平,这正是"同准确率省 57.5% token" headline 的分解版:同样的路由损失预算下,学习策略把更多题分给了便宜臂)。
- 臂能力上限 17.86pp 是四臂集合(direct/rt/wt/prompt)本身的硬约束,不随 λ 或手写/学习切换而变化——要突破这一上限,需要新增更强的臂或改进现有臂的能力,而非调路由参数。

## 4. 已知局限

- 簇级符号检验把每簇折成一票(基于簇内 mean(test)−mean(base) 的符号),丢弃了簇内胜负边际信息;这是保守选择(与朴素符号检验同构,便于并排比较),不是唯一可行的聚类稳健检验(未做的备选:簇级 t 检验、簇稳健标准误的 Wald 检验)。
