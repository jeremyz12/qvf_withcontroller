# 判官侧 token 成本实测(08-17 补测)

> **判决先行:猜想被证实——判官侧成本此前被系统性高估,主因是估算时用错了单价档位(误用 $15/$75 而非 claude-opus-5 实际的 $5/$25 每 Mtok),其次是 token 量级本身也偏高估。补齐实测后,已识别的三处具体"估算"主张(S8 报告 422 次、openslot 报告 ~120 次、B1 报告 P39 S5 101 次未测缺口)全部下修,幅度 2-3 倍不等;全部换算为"实测单价 × 已知行数"口径,不再是估算区间。** 判官稳定性附带核查:155 行独立重判与归档判决**一致率 154/155 = 99.35%**,与既有 20/20 冒烟互补,构成判官稳定性的第二条独立证据。

本轮实测成本(真实 API 调用,非估算)**$0.4770**,占 T2 预算(≤$6)的 8%。

## 三、全局判官成本的实测推算

> 口径声明:以下"实测推算"= **本轮实测单价 × 该主张自身已知/已归档的行数**;不是重新枚举项目全部历史判官调用(那需要盘点全库数百个一次性 dev/pilot/smoke 文件,超出本任务 ≤$6 预算与范围,如实标注为未覆盖,见第五节局限①)。三处具体估算主张逐一替换如下。

### 3.1 S8 完备性套件(A 项):422 次调用

用与 S8 题型profile 最匹配的实测单价(direct/algebra/flat 三臂合并,n=15,$0.002482/次):

**422 × $0.002482 ≈ $1.05**

若改用 155 行全样本的总体均价($0.003078/次)重算:422 × $0.003078 ≈ $1.30。

两种口径均**远低于**原估算区间 $2-6,且区间上限($6)被砍掉约 80%。差距的主因是原估算单价档位错误(≈3 倍),其次是原估算的输入 token 假设(300-500)也比实测均值(≈199)偏高约 1.5-2.5 倍;原估算的输出 token 假设(60-100)与实测均值(≈60)基本吻合。**结论:S8 判官成本实测约 $1.05-1.30,原"$2-6"估算的诚实边界判断("与预算 ≤$8、纪律⑥'达成'方向一致")依旧成立,现在有实测数字支撑而非估算区间。**

### 3.2 openslot 开放槽位修复(B 项):~120 次调用

该文档未给出可独立复核的行数计算过程,本轮**不重新核实 ~120 这个计数**(如实标注),仅替换单价分量。取最贴近该场景(新域复杂查询编译臂判分)的实测单价——S5 复杂查询家族合并均价(S5-314 复杂题 + P39 复杂算子臂 + S8 三臂,共 n=50,$0.002392/次):

**120 × $0.002392 ≈ $0.29**

远低于原估算 $2-3(约 1/8-1/10)。**局限如实声明**:这是跨域代理(proxy)重算——openslot 判的是 P69/P26 两个新域的题目,本轮 155 行采样未覆盖这两个具体域,借用的是"同为复杂查询编译臂判分"这一最近邻类别的实测单价,不是该域自身的实测。若该域题目的 gold/answer 长度显著偏离本次采样的复杂查询臂题目,实际数字可能有出入,但方向性判断(远低于原 $2-3 估算)在合理误差范围内应当成立,因为所有已测复杂查询类别的均价都落在 $0.0021-0.0026/次窄区间内,波动很小。

### 3.3 B1 S5 定稿:P39 复杂查询臂 101 次未落盘调用(C 项)

这是本轮最直接的缺口填补:采样 20 行**同一总体**(`results/wsc_s5_p39_arm.jsonl`,即 b1_s5_corrected 报告中明确指出"该轮跑批未跑到 `_report_usage()` 打印点、判官 token 未被记录"的那 104 行复杂算子臂结果),得到该臂**自身**的实测单价 **$0.002561/次**(均输入 166.0、均输出 69.3)。

b1 报告当时的外推做法是借用**同一批次里 direct 臂**(而非 complex 臂本身)的实测单价($0.3675/104=$0.003534/次)去外推 complex 臂的 101 个未落盘调用,得到 ≈$0.357。但 complex 臂与 direct 臂的判官输入构造不同(complex 臂的 answer 来自查询编译执行结果、direct 臂的 answer 来自检索式直接生成),两者 token profile 不必然相同——本轮用 complex 臂**自身**的实测单价重算:

- complex 臂 101 个未落盘调用:101 × $0.002561 ≈ **$0.2587**
- 加上 b1 报告中已实测的 3 个调用($0.0062):complex 臂 104 次合计 ≈ **$0.2649**
- 加上 direct 臂已实测的 104 次(真实值 $0.3675,原样沿用,本轮未重跑):
- **P39 S5(208 次判官调用)总成本重算 ≈ $0.63**(direct $0.3675 + complex $0.2649)

对比 b1 报告原先给出的外推值 ≈$0.73,**下修约 14%**,方向性结论(P39 S5 判官成本量级在 $0.6-0.8 之间,是小额支出)不变,但现在 101 次未落盘调用的分量不再是跨臂借价的外推,而是基于同一总体(104 行文件)的独立随机抽样(20/104)得到的实测单价 × 已知行数,统计上更可信。

### 3.4 附加量级参考(非三处主张之一,标注为独立补充)

用本轮全样本总体均价($0.003078/次)对项目主线系统臂做一个量级参考:VERSION_LEDGER 明确记录"全体 5511 题"是系统臂(QVF)判分行数,直读基线臂对同一批题目另需 5511 次判官调用,两者合计 11,022 次:

**11,022 × $0.003078 ≈ $33.92**

这**不是**"全项目判官侧总成本"——它只覆盖主线系统臂+直读基线臂两条线,不含 tlcot 提示词臂、mem0 基线、oracle 上界、S1-S7 系列扩展、以及数量庞大的历史 dev/pilot/smoke 一次性调用(这些文件数以百计,未在本轮盘点范围内,见第五节局限①)。列出此数仅为给读者一个"主线系统级判官成本处于十位数美元量级、而非三位数"的粗量级参照,**不应被引用为项目判官总成本**。

## 四、附带核查:判官稳定性(重判一致率)

155 行独立重判 vs 归档判决,**一致 154/155 = 99.35%**,分歧 1 处:

- `lme_ku` 域,question_id=`e66b632c`,knowledge-update 题型。归档判决:正确(判官认为回答同时提到旧值 27:45 与新值 26:30,符合"含更新后答案即算对"的知识更新题判分规则)。本轮重判:错误(判官读到回答最终结论落在 26:30 而非 gold 的 27:45,判定与 gold 矛盾)。核对 gold_answer 后确认:**这是同一判官在同一评分规则边界情形下两次运行给出不同倾向性判读的真实分歧**(回答文本本身包含两个数字,新旧值指代需要判官做语用推断),不是脚本 bug 或数据错误——如实记为判官的天然不确定性个案,不做取舍。

该 99.35% 与此前的 20/20 mock 冒烟(纯管道正确性,非真实一致性测量)互补,构成判官侧稳定性的**第一条基于真实 API 独立重判的定量证据**。样本量 155、单次分歧,置信区间较宽(Wilson 95% CI 约 [96.4%, 99.9%]),但已经是比"未测"更强的信号,建议后续若做更大样本复核时优先覆盖 knowledge-update / abstention 类题型(本轮唯一分歧落在此类)。

## 五、方法与局限(如实记录)

1. **未覆盖全项目历史判官调用总账**。本报告替换的是已被明确点名的三处具体估算主张(A/B/C)+ 一个量级参考(3.4),不是对项目自 08-04 以来数百个 dev/pilot/smoke/一次性对照文件里全部判官调用的逐一重算——那需要先做一次独立的"哪些文件真的调过真实判官"盘点,规模远超本任务预算,如实标注为未做,不假装已覆盖。
2. **B 项(openslot ~120)的行数本身未被本轮复核**,只替换了单价分量;若该数字本身有误,重算结果会同比例偏移。
3. **跨域代理定价存在于两处**(B 项、3.4 节),已在正文逐处标注,不作为域内实测呈现。
4. **重判结论不覃盖归档判决**。155 行的新判决只写入独立新文件,不修改任何已发布报告引用的原始数字——这是本轮任务的纪律边界,不是遗漏。
5. **样本覆盖 8 条实验线、12 个来源文件,但仍是全项目判官调用总体的一个小切片**(155/未知全量);跨类别单价方差不大(全部 12 类均落在 $0.0021-0.0049/次窄区间,唯一偏高的是 lme_ku,因该域答案文本更长、判官需要额外语用推断),但仍建议将本报告的单价视为"当前已知类别的代表性区间",而非放之四海皆准的常数。
6. **本轮实测真实花费 $0.4770**(155 次 opus 判官调用),远低于 T2 预算上限 $6。
