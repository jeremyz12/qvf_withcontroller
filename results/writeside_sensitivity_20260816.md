## 二、第一步:零成本纯代码敏感性(`execute_plan`,零 LLM)

对同一批 76 题(B6 子集)和 48 题(P6 子集),用各轮卡片库重跑
`complex_query_arm.execute_plan(plan, recs, mem_dates, question)`——`plan`
直接复用已归档的编译结果(问题→计划只取决于问题文本,不取决于卡片库,
复用不引入方法学偏差,且这部分本来就是零 LLM)。

### ① 证据包为空的比例

| 库 | 质量 | 证据包为空 |
|---|---|---|
| v42(参照) | 76.88% | 4/76 = 5.3% |
| b6_rep1 | 78.0% | 0/76 = 0.0% |
| b6_rep2 | 68.0% | 8/76 = 10.5% |
| **b6_rep3** | **64.0%** | **4/76 = 5.3%** |
| v42(参照,P6 子集) | 76.88% | 4/48 = 8.3% |
| p6_rep1 | 73.33% | 0/48 = 0.0% |
| p6_rep2 | 80.00% | 0/48 = 0.0% |
| p6_rep3 | 73.33% | 0/48 = 0.0% |

**空证据包比例与"精确匹配率"质量分数不单调**——质量分数最低的
b6_rep3(64.0%)空证据包比例反而低于质量分数居中的 b6_rep2(68.0%,
10.5%)。这与温度诊断报告(`card_temperature_diagnosis_20260816.md`)已
确认的结论一致:精确匹配率衡量的是"抽取内容与源链逐字对齐程度",不直接
等价于"该库能否覆盖某道具体问题所需的槽位"——两者相关但有噪声,不能
互相替代。

### ② 结论行是否跨库一致 / ③ 关键计算值是否翻转

逐题比较 `derived`(结论行文本)与从中摘取的关键计算值(如
`count_changes` 的次数、`longest` 的赢家值等;`trajectory`/`tag_filter`/
`tag_trend`/`join_at_change` 不摘取,按定义不适用):

| 对照(vs v42 参照) | 结论行逐字相同 | 关键值不同(翻转候选) |
|---|---|---|
| b6_rep1 vs v42 | 51/76 (67%) | 9/76 (12%) |
| b6_rep2 vs v42 | 52/76 (68%) | 11/76 (14%) |
| **b6_rep3 vs v42** | 55/76 (72%) | **4/76 (5%)** |
| p6_rep1/2/3 vs v42(各) | 31-32/48 (~65%) | 6/48 (13%,三轮一致) |

**结论行本身跨库有实质差异**(约 1/3 的题结论行文本不同)——这是预期
之内的:不同建卡运行抽到的具体记录条数、措辞、槽位归类都会不同。但
"结论行不同"≠"答案错了":很多差异是措辞/条目数量层面的(比如多抽到
或少抽到一条与该问题无关的记录),不改变最终计算出的关键值。

**关键值相对 gold 的翻转(code-only,粗粒度子串匹配,不经过读者/判官)**:

| 库 | code-only 命中 gold |
|---|---|
| v42(B6 子集内) | 69/72 = 95.8% |
| b6_rep1(78.0%) | 70/76 = 92.1% |
| b6_rep2(68.0%) | 61/68 = 89.7%(全部重建轮次中**最低**) |
| **b6_rep3(64.0%)** | **67/72 = 93.1%** |
| v42(P6 子集内) | 41/44 = 93.2% |
| p6_rep1/2/3(各) | 45/48 = 93.8% |

跨全部 7 个库(v42 + 3×B6 + 3×P6),code-only gold 命中率落在
**89.7%–95.8%**,极差 6.1pp——**质量分数从 64.0% 到 80.0%(16pp 跨度)
对应的下游 code-only 正确率波动只有个位数百分点**,且不单调(最低命中率
出现在中等质量的 b6_rep2,不是质量最差的 b6_rep3)。

**b6_rep3 vs v42(本任务重点对照组)精确翻转计数**
(`scripts/writeside_sensitivity_flip.py`,68 题可判、8 题因结论行格式
未命中摘取正则不可判):

| | 计数 |
|---|---|
| v42 code-correct → b6_rep3 code-WRONG(输) | 1 |
| v42 code-WRONG → b6_rep3 code-correct(赢) | 3 |
| 两边都对 | 64 |
| 两边都错 | 0 |
| **净翻转** | **+2(b6_rep3 略优,噪声内)** |

**唯一的"输"案例**(`wikiP54034-Q3163001_s5b`,`count_changes`)在下面
第三节的端到端跑批中也确实是该轮唯一的判分失败题之一,两条独立证据
(code-only 摘取 与 端到端 judge)在这道题上互相印证,不是摘取正则的
误判。

**第一步判决(纯代码层)**:方向未翻转,且波动幅度(个位数 pp)远小于
质量分数本身的波动幅度(16-20pp)。但纯代码层的"gold 命中"只是粗粒度
子串匹配,不能替代真实的读者措辞+判官裁决——按任务要求,进入第二步
端到端验证。

## 四、必答:方向在区间低端是否稳健

**稳健。**

判据(逐条对照任务要求):

1. **核心主张方向**——编译臂显著优于直读臂——**在质量区间最低的单轮
   实测库(64.0%,低于契约均值 70.0%,落在 95% CI [52.1%,87.9%] 下半区)
   上未翻转**:+34.2pp,簇稳健 p=0.00131,与参照库的 +36.8pp 同方向、
   同数量级。
2. **效应量的收缩幅度不显著**:−2.6pp(b6_rep3 相对 v42 的编译臂自身
   准确率差),簇稳健 95% CI [−15.8%, +7.9%] 跨零,p=1.0。
3. **零成本纯代码层的独立交叉验证同向**:code-only 关键值相对 gold 的
   命中率在全部 7 个已实测库(64.0%-80.0% 质量跨度)中落在
   89.7%-95.8%,波动幅度(6.1pp)远小于质量分数本身的波动幅度
   (最高最低相差 16pp);b6_rep3 vs v42 的精确翻转计数是 +2(净胜,
   噪声内)。
4. **两种独立检验方法(纯代码 code-only 命中率、端到端 read+judge 准确
   率)在同一份最低质量库上给出一致结论**,不是单一指标的偶然结果。

## 五、局限(如实标注,不隐去)

- **覆盖范围**:本次敏感性分析仅覆盖 S5 418 题定稿集中与 B6/P6 子集
  重叠的 19/12 个 uid(76/48 题),不是全部 105 个 uid、418 题。这是因为
  B6/P6 是为"契约质量区间估计"这一独立任务构建的固定子集(50/30 uid),
  不是为本任务专门重建的——复用已有产物是任务明确要求的"零成本部分
  先做",但代价是覆盖面受限于历史子集的选取。**未验证**:P39/P551 域、
  以及 S5 105 个 uid 中另外 86 个 uid 是否也在低质量轮上稳健(缺相应的
  低质量重建库,补齐需要新的建卡预算)。
- **区间下界 52.1% 未直接测试**:契约期望的 95% CI 下界是 52.1%,而本轮
  可用的最低单轮实测点是 64.0%(仍在 CI 内,但不是下界本身)。目前没有
  任何一次独立重建低到 52.1%——3+3=6 次已实测重建里最低就是
  64.0%(b6_rep3)。若要在真正的区间下界上验证,需要要么运气好抽到一次
  更低的重建,要么人为构造一份刻意降质的库(后者引入"是否代表真实契约
  分布"的方法学争议,故本轮未做)。**如实标注**:本报告验证的是"已实测
  的最低轮"而非"区间理论下界"。
- **检验力有限**:19 簇的簇稳健检验能分辨 +34pp 这样的大效应,但分辨
  不出"质量从 76.88% 降到 64.0% 是否让编译臂本身掉 2-5pp"这种更精细的
  效应(CI 半宽 ±12pp 量级)——第三行结果"测不出显著差异"不等于"确证
  无差异",只是本次样本量下没有证据支持"有显著差异"这一更强的说法。
- **code-only 摘取是粗粒度代理**:`extract_key_value` 用正则从结论行摘
  取关键值,8/76(B6 子集)存在正则未命中的情况(摘不出可比较的值),
  这部分题目零成本层面无法判断,只能靠端到端结果兜底(已做,见第三节)。
- **plan 复用假设**:本次端到端验证复用了已编译的 plan,前提是"编译
  步骤只取决于问题文本、不取决于卡片库质量"——这个前提本身是
  `complex_query_arm.py` 的架构事实(COMPILE 阶段"只见问题",见该文件
  docstring),不是本任务的新假设,但如实记录:**本任务没有验证"卡片库
  质量是否会影响编译步骤本身"这一(架构上不应该发生、但理论上可以单独
  测的)命题**,因为架构保证了它不发生。

## 六、与既有归档的关系

本报告**不改判**已归档的写入侧质量区间估计本身(`results/card_quality_b6_interval_report_20260816.md`
的 70.0% CI[52.1%,87.9%] 保持不变,`card_temperature_diagnosis_20260816.md`
的温度归因判决保持不变)——本报告解决的是一个不同的问题:"这个已知的
质量区间,是否会威胁到下游主张的方向",答案是"在已实测的低端不会"。
