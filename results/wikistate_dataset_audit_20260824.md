# WikiState 数据集缺陷审计(2026-08-24,$0 机械审计)

来源:批 2 验尸偶然发现差一错误后,对 418 题聚合集做的系统性审计。
**全部为机械可复算结论,无 LLM 参与。**

## 缺陷一:金答案分布高度倾斜 → 平凡常数基线过高(最严重)

| 题型 | 平凡策略 | 得分 | 对照:直读臂 |
|---|---|---|---|
| change_count | 恒答 "2"(不看语料) | **66.7%** | 23.8% |
| count_before | 恒答 "1"(不看语料) | **66.7%** | 51.4% |
| longest_tenure | 恒答链首值 | 46.6% | 42.7% |
| first_vs_last | 无平凡解 | — | 75.2% |
| **三型合计(第四型算 0)** | | **45.0%** | 全集 48.3% |

gold 分布:change_count 70/105 是 "2";count_before 70/105 是 "1"。

**后果**:①一个不读语料的常数基线几乎追平直读臂(45.0 vs 48.3);
②审稿人必问的 majority-class baseline 在本数据集上很难看;
③直读在 change_count 上 23.8% **低于常数基线 42.9pp**——说明它不是在猜众数,
而是被差一系统性带偏(58/105 恰好 +1)。

## 缺陷二:longest_tenure 存在绝对捷径

**金答案是链尾值的比例:0/103 = 0.0%**。原因是末段开放区间按 0 天计的约定,
使最新状态永远不可能赢。任何系统只要学会"排除最新值"就能免费提升。
这是可利用的规律性,不是随机噪声——**捷径可学习 = 该型分数不可信**。

## 缺陷三:change_count 题面歧义(已进批 3 实验)

"How many times did I change my employer?" 对"初次任职是否算一次变更"无定义;
金答案取 N−1(转变数),模型系统性取 N(状态数)。四臂差一率:
直读 58/105、filter 48/105、编译 14/105、smoc 13/105。
**编译臂的优势有相当部分来自执行器 `len−1` 把口径钉死,而非计算能力。**

## 处置建议(按优先级)

1. **必须做(论文级)**:所有对外表格加 **majority-class baseline 行**;
   change_count 与 count_before 的绝对分数一律与该基线并列报告;
2. **数据集下一版必修**:
   - 平衡金答案分布(按目标分布采样链长,使众数占比 ≤35%);
   - longest_tenure 改约定:末段按"至问题日期"计入,或题面排除最新段;
   - change_count 题面写死口径,或金答案接受 N/N−1 双解;
3. **本轮已做**:批 3 澄清口径对照(测量歧义造成的伪影量)。

## 对既有结论的影响(如实标注)

- 编译臂 83.73 vs 直读 48.33 的**总差值不受影响**(远高于平凡基线 45.0),
  但**分题型解释必须改写**:change_count 与 count_before 两型的部分差值来自
  口径与分布,而非结构价值;
- 三段定价的"计算 +6.5"须在批 3 结果出来后重新定价;
- longest_tenure 该型绝对值本就有"不得单独引用"注记,现补上定量理由(0/103)。
