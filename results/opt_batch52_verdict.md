# 批 52 判词 — 两个 harness 基线:读时从整份记忆抽表再答、带工具的 agent 循环

问题(用户):对手不该只是直读,该是"harness 工程"。本批把 harness 在读时能做的两件事做成基线,与 QVF 账目臂在同一 140 题(36 链)上配对。脚本 `scripts/b52_readtime_harness.py`、`scripts/b52_tool_agent.py`;判官 qvf.judge.ClaudeJudge(与所有臂同);题集 `results/b35_questions_sample36.jsonl`。

## 0. 判决(先判决,后数字)

- **弱读者(haiku-4.5):两个 harness 都显著低于 QVF 账目,也低于全文加协议。** 读时抽表 85.0,对账目 95.7 低 10.7(McNemar p = 0.004),对全文加协议 92.9 低 7.9(p = 0.035);工具 agent 76.4,对账目低 19.3(p < 0.001)。每题成本是账目的 4 到 5 倍。
- **强读者(Sonnet 5):读时抽表与账目打平,工具 agent 也打平,但每题成本是账目的 4 到 5 倍。** 读时抽表 92.9 对账目 v52f 92.9(p = 1.0);工具 agent 92.1(p = 1.0)。两者都低于 v47skf 账目 95.0 和整份记忆朴素读 97.1。
- **同一抽取器写时建卡也优于读时建卡。** haiku 写时建的 v45 店账目 91.4,haiku 读时抽表 85.0,差 6.4;写时一次读全库、结果被反复用,读时按题抽每次都可能漏。
- **结论句**:QVF 的账目表示不是 harness 做不到的东西,强读者在读时重做一遍能拿到同样的分;QVF 的价值是把这一步挪到写时并摊销——同一准确率下每题成本降 4 到 5 倍,弱读者上则是准确率本身高 10 到 19 个点。这与三条件主张一致,并把"为什么要写时建卡"从论证变成数字。

## 2. 两个 harness 怎么做的

- 读时抽表:每题两次调用。第一次读整份 transcript(与 fullplain / smw 臂同一渲染),按题目槽位用结构化输出抽出全部"本人开始持有该槽位某值"的记录(value、stated_date、逐字原句);第二次把记录按日期渲染成与 render_card_ledger 相同的三列账目,套 SMW_PROMPT 协议作答。等于把 QVF 的建卡按题在读时重做。
- 工具 agent:模型看不到记忆,只能调四个纯代码工具(列会话、子串搜索、读会话、算天数),最多 10 步(Sonnet 8 步),末行 ANSWER。haiku 平均 5 到 6 步,Sonnet 3 到 5 步。

## 3. 读法

- 弱读者上读时重做输在两处:抽取本身不稳(count_before 78 对 92),以及每题都要读 14.6K token 的原文,而写时建卡只读一次。工具 agent 更差,因为它要自己决定搜什么,漏搜就漏状态,change_count 只有 61。
- 强读者上三种做法在 92 到 93 之间不可分,朴素读全文 97.1 最高。这一格里 QVF 只剩成本:$0.010 对 $0.040 到 $0.047,每题读 1.3K 对 15K 到 20K token。
- 这两个基线把"harness 工程"的强形态测到了;还没测的是带代码执行工具的 agent(自己写脚本计数),预计与工具 agent 同量级。

## 5. 边界

- 只在 14K 库上测;104K 库上读时抽表每题要读 104K token,haiku 无法完成(批 33-D 全文 7.5),Sonnet 每题 $0.30。
