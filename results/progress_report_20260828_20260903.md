## 二、对照发现的不足,以及怎么修的

**发现**:WikiState 的填充会话来自 STALE 混音语料,构建时只做了主题去重,没有筛"第一人称、同槽位的状态断言"。
结果是填充里混入了"我刚升任高级客户经理"这类句子,与金标链同槽位,让计数型金标系统性偏低。
规模:机器初判 47/144 链受影响;Fable 全量重裁确认 72 条断言 / 50 链(34.7%)。
因果:受污染链上计数型判错 45 例中 34 例(76%)是"模型数得比金标多",即金标错、模型对。

**修复(四刀,全部手术式删句,不改金标、不改锚点)**

| 版本 | 做法 | 删除 |
|---|---|---|
| v2.1 | LLM 确认的断言句 | 84 句 |
| v2.2 | 同会话回声(含助手复述) | 70 句 |
| v2.3 | 槽位定向的机械规则(如 "was recently promoted") | 73 句 |
| v2.4 | 对 1,100 个去重填充会话做**穷尽**池审计(它们被复用 4,320 次) | 20 句 |

合计 247 句,语料 −0.42%,542 个链锚全程逐字保留;v2.2/v2.3/v2.4 三版全库分数统计不可分 = 饱和。
效应:账目臂 82.64 → 90.45(+7.81,p=1.6e-05;簇 CI [+3.0,+12.7]);检索臂 48.61 → 48.26(p=0.86,同嵌入器下 top-10 重合 0.995)。
**污染税随"臂把抽取状态提交进可计数账目的程度"而增**(读取量最大的 smw 只 +4.59):检索臂几乎不受影响——所以清洗**放大**了结构总价(+34.0 → +41.8,v2.4 口径)。

**清洗规范(已进 datasheet 草案)**:对池不对实例过滤;闸判据 = 用户本人 employer/position/residence/team 的可识别状态或转移;他人工作/住处、计划、在读、旅行为合法干扰白名单。

**金标本身的残留**:55 条残余失败里金标+判官类 4 条(7.3%,CI 2.9–17.3);完美金卡臂残差 29 条里错标 0、"约定欠定"19(占位日期 YYYY-00-00 的解析、截止日语义);longest_tenure 头两名任期差 ≤1% 的 16 题错误率 37.5%。这一块的修法是把约定写进 datasheet 与生成器,并处置 16 道近平局题。

**新建冻结保留集**:40 链 / 160 题,来自从未碰过的 Wikidata 切片,与开发场零交集,按同一套规范构造,污染残余 0。

## 四、QVF 每一步为什么带来提升,带来了多少

**一句话主轴**:直读失败不是"检索不到",而是"证据以乱序、无日期、含他人状态的碎片形态到场,弱读者算不动"。QVF 的每一步都在把证据往"可计数的、带日期的、只属于本人的状态账目"推。

### 逐段定价梯(同一语料、同一读者、同一判官,配对 McNemar)

| 段 | 做什么 | v2.0 语料 / v42 店(576) | 干净子集(332) | v2.4 语料 / v45 单店(576;中间三段用回填 slot_class 的派生店 v45k) |
|---|---|---|---|---|
| 0 直读 | top-10 检索 + 原文 | 48.61 | 49.70 | 47.57 |
| 1 选择(filter) | 只保留与问题槽位相关的卡片 | 62.67(+14.06,p=1.5e-8) | 68.67(+18.98) | 65.62 |
| 2 认证(usability) | 剔除无日期/无法定位的卡 | 65.62(+2.95,p=0.036) | 74.40(+5.72,p=0.0019) | 66.32 |
| 3 计算(compile) | 按日期排序、合并相邻同值、执行器计数 | 75.87(+10.24,p=1.8e-9) | 85.24(+10.84) | 79.69 |
| 4 账目 + 协议(smoc) | 全账目渲染 + 两段式状态追踪协议 | 82.64(+6.77,p=1.3e-4) | 92.17(+6.93) | **89.06** |

六段方向在 v2.0 与 v45 两种口径下一致(干净子集只算了四段);干净子集上每段都更大(污染只罚结构化臂)。中间三段在原 v45 店上因字段回退只有 58.68 / 60.59 / 77.78,派生店 v45k 恢复到与 v2.0 存档不可分。v45 单店口径是可引用头条:**89.06 vs 47.57,+41.49,簇 CI [+36.6,+46.4]**。

### 每一步的机制证据(为什么是"因为它",不是"碰巧")

1. **选择为什么有效**——不是检索缺口。完美金句证据喂给直读只到 76.7,比账目臂还低 13.7(p=8e-11);检索覆盖率四分位单调(6.2→60.8)只解释三分之一失败。选择的价值在"把他人/无关状态排除出计数池":无填充对照实验里,去掉填充会话直读升 22.5、全文升 20.0、账目只升 1.7 → 结构溢价的 **44% 是抗干扰**。
2. **计算为什么有效**——剩下 **56% 是抗聚合**:计数型题(change_count / count_before / longest_tenure)是弱读者的死穴,全文上 change_count 只有 29.9;账目把"数转移"变成读表。
3. **压缩本身没有贡献**——同 token 预算的无结构摘要 52.78 = 全文 52.26(p=0.89);结构束(摘要 → 裸账目)+22.57(p=2e-21);锚点(逐字 source_span):去锚 77.26 vs 82.64,−5.38(p=1e-04)。
4. **协议是脚手架,只对中档读者**——F.1 两段式协议在 haiku 上 +10.9(p<1e-6),在 gpt-5-mini 上 −3.5,在 Gemini 3.6 Flash 上 +0.35(n.s.)。所以论文口径:结构抬升的是弱/中档读者,协议按厂商分布。
5. **"写时"两字的证据**——读时才建账目(对 top-10 会话抽取)只有 60.24:检索覆盖齐时 85.3,缺一个会话就掉到 15.9。写时卡的价值 = 覆盖完整。
6. **上界**——完美金卡 94.97(写侧余量只剩 +4.5);剩余 55 条失败:写侧 69%(其中 76% 是值抽到了但槽位名不合)、读侧 24%、金标+判官 7%。
7. **三种有效性**——现值(S1)+8.3、点时(S2)+59.0、历史聚合(S3)+34.0(v2.0 口径;v2.4 单店 +41.5):账目对"某时刻我在哪"这类查询条件化问题优势最大。

### 伪代码(每步一块,便于汇报)

```
WRITE(sessions):                       # 写时,批量跨会话
  for s in sessions (by date):
    cards += LLM_extract(s)            # 每张卡: slot, value, stated_date, source_span(逐字), entity/owner
  return cards                         # 不裁决、不合并,只记录

READ(question, cards):
  pool   = select(cards, slot(question))        # 1 选择:同槽位 + 本人
  pool   = certify(pool)                         # 2 认证:有日期、能定位到原句
  ledger = compile(sort_by_date(pool))           # 3 计算:合并相邻同值,得到状态序列
  answer = reader(PROTOCOL, render(ledger), q)   # 4 协议:先列状态轨迹,再作答
```

### 成本侧
同精度下账目读取 2,539 tok vs 同协议读原文 13,968(1/5.5);槽位投影 1/11.6–1/17.8。
规模轴上账目也衰减但慢得多:104K 库全账目 54.2@20.9K、投影 61.7@8.8K,haiku 全文 7.5@103.8K;
对便宜推理读者(gpt-5-mini 全文 65.0)成本优势只剩 1.4–2.6 倍,"5 倍"口径已撤回。

## 五、WikiState 与 QVF 相比竞品的优势

**WikiState(基准)**
- 十家同类基准对标:κ 报告、判官效度验证、成本三项、版本纪律四项全场领先;差距在"未公开、人工覆盖低"(现已有保留集与第二轮核验在路上)。
- 效度硬指标:542 锚点逐字机核、闭卷污染 0.69/7.81、判官机械一致 97.2% 可复现、顺序不变性 n.s.、格式伪影已定价、金标污染有因果证据并已修复。
- 结构上的独特性:一条链 = 同一槽位的多次**取代**,题型覆盖现值 / 点时 / 历史聚合三种有效性;第三人称同槽干扰与更正题作为难度轴。

**QVF(系统)**
- 与 18 个对手实跑同台(另 2 个阻塞;60 题标定场,同读者同判官):QVF 编译臂 83.3 / 账目臂 86.7(同 60 题文件实测,编撰旧值 85.0 已更正);最强对手 timeline 63.3、Letta 式文件系统 agent 56.7、HippoRAG 2 55.0、直读 51.7;MemOS 45.0、A-MEM 43.3、LangMem 40.0、TRACE 30.0(公平配置)/16.7、Mem0 26.7、Graphiti 3.3、LightRAG 1.7。
- 对手的共同病灶:**检索赢、裁决输**。HippoRAG 2 把整条链 85% 送进上下文仍只有 56.9;MemOS 写时扩张 4.1 节点/会话而非整合;TRACE 的"取代边"在默认配置下一条不生成。
- 分界句:对手把"有效性"当写时一次性标量(Zep/TRACE/MemStrata),QVF 把有效性当"记忆 × 查询"的函数,在读时按查询重推。
