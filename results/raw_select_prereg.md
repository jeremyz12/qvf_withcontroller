# 预注册:原文选择臂(raw_select)——给"+18.4 筛选价"测纯选择下界(先于跑数提交)

日期:2026-08-20。来源:持续优化循环 rank-4(首轮攻击面审计)。

## 动机(攻击原文)

filter-only 臂的证据行由 `_chain(_select_pool(...))` 生成:按日期排序、相邻同值合并
(一行恰好=一次转移)、槽位归一、计数卫生化——这些是代码执行的**计算**,却全部计入
"筛选 +18.4"。若把同一选集换成原文轮(无任何规范化),成绩掉到提示词臂水平,
则"纯选择价"未被证实。

## 本轮 $0 子分析(已做,先记录)

filter 臂计数两型的"行数−1==gold"条件准确率(results/wsc_s5_filter_only.jsonl):
- change_count:行数对上 42.9%(77 题) vs 对不上 **3.6%**(28 题)——正确性强依赖
  "交付可数行集",该型增益含结构性成分,单独标注;
- count_before:对上 100%(仅 3 题) vs 对不上 **83.3%**(102 题)——读者自己做
  日期过滤,非结构编码。两型必须分开叙述。

## 设计

- 实现:`complex_query_arm.py` 新增 `QVF_READER_MODE=raw_select`(冻结文件纪律:
  env 旗标、默认关、关时逐字节等价)。证据 = 与执行器同一 `_select_pool` 选集
  (plan.slot;join 题并入 slot2),渲染为直读格式 `[session_date] 原始轮文本`,
  按会话时序、同轮去重、`EVIDENCE_CAP` 同上限;无槽位标签/值抽取/相邻合并/卫生化。
  与 filter 臂的差 = 规范化+排序+去重+值抽取的合计贡献。
- 考场:WikiState 聚合 418 题的**分层子集 100 题**(每题型 25,qid 排序后等距抽取,
  无随机数);同卡片库(results/wt_cards_v42)、同读者(haiku-4-5)、同判官。
- 对照:提示词臂(47.61%)与 filter-only(66.03%)在**同一 100 题子集**上的归档行复算。

## 判据(先写死;全部在同子集同题配对上判)

设 R = raw_select 子集成绩,W = 提示词臂子集成绩,F = filter-only 子集成绩:

1. R ≥ 60% 或 (R−W ≥ +10pp 且 McNemar p<0.05)→ **纯选择价成立**;
   +18.4 拆报为"选择下界 (R−W) + 规范化增量 (F−R)";
2. R−W < +5pp 且 n.s. → 纯选择价**未证实**,对外头条改写为
   "筛选+规范化联合价 +18.4",limitations 声明选择与计算在本语料不可分;
3. 中间 → 报三段连续谱(W → R → F),不下二值判决。

change_count 型在任何判决下都单列"含结构性编码成分"注记($0 子分析已证)。
无论方向如实入档。预计成本 ≤$1(100 题 × 编译+读者+判官)。
