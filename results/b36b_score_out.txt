# Batch 36b — SAME-READER (claude-sonnet-5) rerun of the QVF ledger arm and two reference arms

Why: batch 36 compared plainctx@sonnet-5 against smoc@haiku-4-5 — a CROSS-READER contrast. This batch reruns smoc / direct / fullplain with reader claude-sonnet-5 on exactly the same 140 questions so the comparison is within-reader.

Runner: scripts/lb_reader_arm_b36b.py (copy of the frozen scripts/lb_reader_arm.py; the ONLY differences are --max-tokens (default still 800), --workers (default still 1), --budget, and extra logged fields. Prompt construction for smoc / direct / fullplain is copied verbatim from the original main()).
Sampling params: the ORIGINAL lb_reader_arm.py already sends temperature=0 only when model.startswith('claude-haiku'), so claude-sonnet-5 was never sent temperature — no guard had to be added; the copy just makes that explicit (_wants_temperature). Verified empirically: claude-sonnet-5 returns 400 '`temperature` is deprecated for this model.' (and the same for `top_p`), and succeeds with neither parameter.
max_tokens = 4000 for every sonnet-5 run in this batch (recorded per row as reader_max_tokens). Reason: sonnet-5 has extended thinking on by default and max_tokens caps thinking + visible text together; batch 36 lost 20/140 questions to the 800 cap.
Corpus data/wikistate_full_ALL_v24.json (v2.4); store results/wt_cards_v45 (READ-ONLY, not rebuilt); questions results/b35_questions_sample36.jsonl (140 q / 36 chains); judge qvf.judge.ClaudeJudge() = claude-opus-5.
