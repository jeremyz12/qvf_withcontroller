## 三、这对论文意味着什么

### 作废的

**"LoCoMo/LME-KU 缺少可追踪的结构化状态变化,故为适用边界"——这条对 KU 不再成立。**KU 上的负结果主因是分批建卡的身份碰撞把卡片图折叠了(38.7% 记录碰撞 → 并查集分量塌陷),不是语料性质。凡引用 KU 作为适用边界证据的地方一律撤回。

### 新增的、可主张的

1. **一个真实的失效模式 + 解**:抽取-执行范式在**长历史库**上会因分批而结构性退化——模型每批从 `r1` 重新编号,合并后身份碰撞,把不同事实折叠成图上同一节点。**跨批身份保持是它的解,值 +16.67pp(CI[+7.7, +26.9])。**该失效模式对任何"分批抽取 + 图结构记忆"的系统都成立,而据现有核实档无人报告过。
2. **"永不比基线差"这条契约在 KU 上首次达成**:80.77% > 78.2%。
3. **逐字溯源契约违约率的语料敏感性**(11.0% vs 28.26%),对所有用合成数据验证溯源机制的工作构成警告。

### 仍然成立的负结果(不受本轮影响)

**提示词臂 92.31% 仍显著高于修复后的卡片臂 80.77%**(p=0.022)。即"**对浅更新类问题,一段 2.7k token 的指令仍优于结构化卡片路线**"这条工程规则**不变**——变的只是"卡片路线不再比什么都不装更差"。

## 四、实验设计:单变量已达成(初稿担心的温度混淆并不存在)

**本文件初稿写"本轮动了两个变量(重编号 + 固定温度)"—— 那是错的,已更正。**

实测建卡成本 **$0.2056/uid**,78 uid 外推 **≈$16.0**(归档 usage 字段独立给出 $14.96,两者一致),**超 $8 预算一倍**。因此没有走 LLM 重建,而是改成**离线派生**:

从归档卡片库直接派生新库(**零 LLM 调用**),记录内容、槽位、日期、关系边、抽取顺序**逐字不动**,只把 `record_id` 唯一化并同段重映射 `relation_target_record_ids`。

**这比重建更干净**:重建会同时重掷抽取随机性——证据在手,同一 uid 重建出 **102 张卡 vs 归档 160 张(−36%)**;若走重建路线,"卡片库"这一个变量里会混进抽取方差、温度口径、批次切分三个混杂因子。**离线派生把变量收敛到 `record_id` 这一个量,温度混淆在设计上被绕过。**

**离线分段 = 真实批次边界(已证实,非假设)**:78 个 uid 全部被字符预算切成**恰 2 个顶层批次**;74/78 恰好 2 个 id 段,4/78 只 1 段(且这 4 个零碰撞);**没有任何 uid 的段数 > 批次数**,即递归对半分批从未产生额外的 `r1` 重置。代码路径验证重建(1 uid,$0.21)复核:前缀集合恰为 `{b0, b1}`、`n_batches=2`、碰撞 0。

**它同时是代码内修复效果的上界**:离线分段在每处 `record_id` 重置切段,粒度不粗于 `QVF_CARD_RENUMBER=1`。故若此臂达不到门槛,代码修复更达不到——判据 C 的逻辑不被该替换削弱。
