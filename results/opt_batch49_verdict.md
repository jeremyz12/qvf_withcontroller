# 批 49 判词 — 最新 QVF 是不是只对 WikiState 特调:四格补齐 + 两个第三方考场 + 三组对照

预注册:`results/opt_batch49_prereg.md`(含中途的 KEYS 修正记录)。评分 `scripts/b49_score.py`、`scripts/b48_score.py`、`scripts/b47_score.py`。既有店与结果文件只读。

## 0. 判决(先判决,后数字)

- **H1(特调检验)被证实:特调的是 Stage 1 的槽位查询,不是方法本身。** 四类查询的两阶段建卡在 STALE 从 61.7 掉到 43.3(−18.3,p = 0.004,低于直读 46.7),在 MemOps 从 52.5 掉到 25.8(−26.7,p = 1e-6);15 类通用查询收回一半(STALE 50.0,MemOps 42.5),仍低于全量抽取。**关掉 Stage 1、保留另外三项修复(精简 schema + 闭集槽位规则 + 值规范化 + 蕴含过滤)的对照在同样的店上不掉分:MemOps 50.0 对旧建卡 48.3(+1.7,p = 1.0),对直读 +8.3;STALE 见 §3(待补)。**
- **WikiState 上的提升不需要 Stage 1。** 关掉 Stage 1 的通用配置(v53sf,36 链)haiku 140 题 95.7,与开着 Stage 1 的 v52f 在同一 140 题上 95.7 / 94.3 相同(p = 1.0 / 0.75),对 v48f 90.0 高 5.7(p = 0.10,n = 140)。全量 144 链上开 Stage 1 的 v52f 两轮 95.36 / 94.82,对 v48f 89.82 / 90.18 高 4.6 到 5.5(p = 1e-4 / 1e-3,144 链簇自助 95% CI [+2.2, +8.9] / [+1.3, +8.1])——这是本项目第一次写侧改动让读者显著上升。
- **H2(强读者 ≥ 95.0)被否定,但差距不显著。** v52f@sonnet-5 140 题 92.9,对 v47skf 95.0 −2.1(p = 0.61),对 v45 90.7 +2.1(p = 0.65),对存档措辞全文 84.8 +8.0(p = 0.04);对整份记忆进 prompt 的 97.1(批 36b,mt4000)仍低 4.2。批 48 的无 KEYS 配置 v51f 是 88.6(−6.4,p = 0.049),原因是模型把职位并入雇主值,KEYS 闭集规则修复了它。
- **H3(104K:haiku ≥ 61.7,sonnet ≥ 74.2)一半证实。** haiku 全账目 70.0(旧 54.2,+15.8,p = 0.003)、投影 71.7(旧 61.7);sonnet 全账目 72.5(旧 73.3,p = 1.0)、投影 70.8(旧 74.2,p = 0.62);输入 token 降 93%–94%。104K 店用的是带 Stage 1 的配置,这一格是 Stage 1 该用的场景。
- **H4(成本 ≤ $20)被否定。** 建店、蕴含、读者、判官合计约 $38(§6),超支来自中途加的三组对照(KEYS 修正重建 144 链、无 Stage 1 对照两考场 + WikiState)。

**结论句(可直接进论文)**:评审建议的四项写侧修改里,精简 schema、闭集槽位规则加值规范化、语义蕴含过滤三项是通用的,在 WikiState 上把弱读者从 90 提到 95,在 MemOps 上与全量抽取持平;两阶段抽取的 Stage 1 若用固定槽位查询实现则是数据集特调,在两个第三方考场上崩到直读以下,只能作为"大库 + 领域已知槽位"场景的可选组件(104K 上弱读者 +15.8、token −93%)。评审原话的 Stage 1 是"cheap model / embedding / rule"的事件定位,不分槽位;廉价模型逐句判断的版本尚未测。
