# 预注册:优化批 3——计数口径澄清对照(自我攻击,先于跑数提交)

日期:2026-08-24。来源:批 2 验尸发现**系统性差一(fence-post)错误**:
WikiState change_count 上,直读 58/105、filter 48/105、编译 14/105、smoc 13/105
的答案恰好比金答案多 1(模型数"状态个数",金答案数"转变次数"=N−1)。

## 这是对我方主张的攻击面(必须自测)

若差一全部算对:直读 23.8→79.0、编译 73.3→86.7。即**编译臂在计数类上 +49.5pp 的
优势可能大部分来自"执行器把口径钉死"(len−1),而非"代码会算"**。
若成立,"计算段 +6.5"与"计数类只有结构买得到"两处口径必须收窄。

## 设计(单变量:只加一句口径说明,三臂同等对待)

在题面后追加同一句(所有臂逐字相同):
`(Count only transitions between different values; the initial value does not count as a change.)`
考场:WikiState change_count 全部 **105 题**;臂:直读 / 编译 / smoc 各一次重跑。
其余(读者、判官、证据构造、卡片库)与归档逐字节一致。

## 判据(先写死)

1. **C1 口径伪影量**:直读增幅 ≥ +30pp → **判定"现行 change_count 分数主要测的是
   约定猜测而非计数能力"**;对外一切 change_count 口径改为"澄清口径下"报告,
   并在数据集文档中登记该型题面歧义为已知缺陷;
2. **C2 结构价残值**:澄清口径下 编译 − 直读。
   - ≥ +15pp → "结构在计数类仍有实质价值",三段定价该型保留(数值更新);
   - < +15pp → **收窄**:计算段在计数类的价值主要是口径固化,如实改口;
3. **C3 smoc**:澄清口径下 smoc vs 编译臂,决定新最优配置的题型归属。

## 可证伪预测

直读 → 70-82;编译 → 84-90;差值从 +49.5 收缩到 +5~+15。
