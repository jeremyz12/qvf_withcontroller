# 批 32 预注册:v3 难度轴——更正撤回 + 条件计数 + 第三人称同槽位干扰(2026-09-02)

铁律:**让读者更难,不让金标更错。** 所有新题金标由链机械算出;干扰项一律第三人称。
可行性:144 实体零跨槽位重叠 → 真多槽位连接需重拉 Wikidata,延后;条件连接改为
链内两锚点间的范围计数(仍是"答案取决于查询条件"的构念)。

## 32-A 新题型(语料 C = v2.4 + 每链一处更正会话)

- **correction**:随机选第 r 行(r≥1),把其日期改为 new_date(在前后行之间,
  ±6 月);在原声明会话之后插入更正会话(chain_index="corr"):用户"更正——我
  实际是 new_date 开始 value,不是 old_date";助手确认。派生两题:
  `correction_date`("我何时开始 value?"→ new_date)、`correction_count`
  (在 old/new 之间取边界的 count_before,金标随更正翻转);
- **scoped_count**:"从开始 X 起、到开始 Y 之前,我持有过几个不同的 slot 值?"
  (i<j,j−i≥2),金标 = j−i;按索引计,对更正稳健;
- 各 144 → 432 题;臂:smoc(账目)+ direct;读者 haiku;判官 ClaudeJudge;
- 判据:A1 新题型有区分度 = smoc 与 direct 差 ≥15pp 且 smoc <95(非天花板);
  A2 更正题上 smoc 若 <70 → 标记为"撤回处理"能力缺口(写入 limitations,
  与 MemStrata 写入盖章路线的对比素材)。

## 32-B 第三人称干扰(语料 D = v2.4 + 每链 6 个第三人称同槽位干扰会话)

- 干扰值取自**同槽位其他人设**的真实链值(与本链值不重合),以固定模板渲染
  为用户谈论他人("My cousin Dana just started at X"),日期落在本链时间跨度内,
  chain_index=None;金标不变(第三人称);
- 测原 576 题(四型),对比 v2.4(smoc 90.45 / direct 48.61);
- 判据:B1 direct 掉幅 > smoc 掉幅(相似度检索被同槽位值吸走,账目按归属
  过滤)⇒ "干扰同质化不伤结构化系统";B2 若 smoc 掉幅 >5pp ⇒ 写侧误把他人
  状态建卡,记为写侧缺陷并进 limitations;
- 预算:两次 144 店建库 ≈$12 + 读取 ≈$8 ≈ **$20**。

统计:配对 McNemar;所有绝对分挂语料版本(C/D)与店版本。

## 中期发现(2026-09-02,direct-C 落地后):32-A 两型被证伪为"查找可解"

**新证据**:direct(top-10 检索)在新题型上 88.4%,远高于其原四型的 48.61:
correction_date **100%**、scoped_count 86.8%、correction_count 78.5%。
**机制核验(离线复现检索,results/b32_retrieval_check.jsonl)**:direct 的
top-10 在 **100%** 的题上含更正会话,在 98–100% 的题上含 ≥2 条链锚句。
**结论修改(依据=上述可复现数据)**:
- correction_date、scoped_count **不测状态追踪,只测词面检索**——更正句
  "I actually started at X on DATE" 就是答案,问题几乎逐字复述;scoped_count
  点名 X、Y 两锚句,检索直接命中。判据 A1 对这两型**不成立且不可能成立**
  (direct 已近天花板),原因是出题失误,非系统能力;
- correction_count(78.5%)留有 ~20pp 空间,是三型中唯一可能有区分度的,
  等 smoc-C 落地后单独裁决;
- 判官日期等价:机械核验 144/144 与判官一致,无问题。

**设计教训**:真正的撤回/条件测试必须让答案**不能从单句读出**——即更正只
改变一个中间量,问题问的是该中间量参与计算后的结果(如:更正开始日期后,
"你在 X 待了多久 / X 与 Y 谁更久"),使检索到更正句本身不够,还得与其他
行合并。此为 32-A′ 候选设计,**待用户令,不自动追加支出**。

### 结论修正(2026-09-02,新证据:逐卡检视)

上一条"写侧不区分陈述归属"**表述过度,撤回**。逐卡检视显示干扰值虽被建卡,
但 slot 标为 `family_member_education` / `coworker_employment` 等**他人槽位**,
`claim` 明写 "User's brother Sofia attends…",归属完整保留。**写侧归属正确**;
风险点转移至**读侧渲染**——账目是否把异槽位卡一并渲染给读者。真混淆率
(卡 slot == 本链 slot 且值为他人状态)另行统计见上;smoc-D 终值量化净效应。

### 再修正(逐卡 + 渲染器检视,更精确的表述)

- **写侧**:归属文本保留(claim "User's cousin…"、span 逐字),但 `slot` 字段
  **43%(287/668)被标成本链槽位**(如把表姐的雇主标为 `employer`),涉及
  55/144 链;其余 381 张标为他人槽位(family_member_education 等);
- **读侧**:默认视图 `QVF_LEDGER_VIEW=""` **不按槽位过滤,全部渲染**;`slot`
  视图才过滤——但即便过滤,那 287 张标错槽位的卡也会漏进来;
- 因此净效应取决于读者是否据 claim/span 文本识别归属。smoc-D 终值即答案;
  若掉幅大,修复应在**写侧 slot 标注**(归属闸)而非读侧过滤。
- **渲染格式**(repro_batch3 默认视图):`[entry n] date | slot: value — "span"`。
  干扰卡即使 slot 被错标为 employer,其 value 也含人名("Sofia at University
  of Cambridge")、span 逐字含 "My brother Sofia…"——**归属线索对读者可见**。
  故净效应 = 读者据 value/span 排除他人状态的纪律;smoc-D 终值裁决。
